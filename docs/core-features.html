U UE Cache Manager Operator's Manual · Core Functions
UECM · 三层缓存定位

把 UE 工程在多机集群上的
零编译启动、零卡顿运行集中化、自动化、可视化。

面向 VP / XR 渲染集群的 TD 和 IT 运维：5–20 台 Windows render node，操作直接对接拍摄现场。 下面 3 个核心功能按操作顺序覆盖 UECM 的主路径：① 状态刷新与集群诊断（先看清现状）→ ② 开通与授权（让机器可被远程管）→ ③ DDC 缓存工作流（含 PSO，缓存落地）。其余 system / winrm / cred / env / gpu / project / 单条 INI 编辑等域是底层支撑，不单独成核心。

L1 · DDC

Derived Data Cache

消除 Shader 重编译。两条 backend：legacy .ddp pak（UE ≤ 5.3）与 zen daemon 原生缓存（UE 5.4+），由 ddc --backend auto 自动路由。

L2 · PSO Precaching

引擎主动预创建

UE 5.1+ 加载关卡时主动预创建 GPU pipeline state，消除场景切换卡顿。

L3 · PSO Cache 文件

兜底缓存

采集 .upipelinecache / .stablepc.csv，兜底 Precaching 漏掉的边缘组合。

  1. 01 状态刷新与集群诊断
  2. 02 开通与授权

01

状态刷新与集群诊断

machine ini health

操作的第一步是「看」——先发现集群里有哪些机器、各自什么状态，再体检配置正确性和运行可达性。这一步只读，不动任何配置。组合起来回答三个问题：机器活着吗 / 配置对吗 / 哪里不对、该怎么修。但 health / ini scan 是横切工具：开通（②）后要复验、部署缓存（③）后更要回跑确认生效，不是开工前用一次就完。

扫 CIDR 发现机器（5985 / 445 / 135） refresh 读 UE 版本（注册表）+ GPU（WMI） ini scan 查配置 health run 出 24 项矩阵
$uecm-cli machine scan 192.168.10.0/24
$uecm-cli machine refresh 3 --cred-alias prod
1a · INI Scanner

配置正确性

base 规则 R001–R025 扫 project / user / engine 三级 INI：硬编码 DDC Path=、user 级覆盖、deprecated CVar、PSO precaching（R008–R010）、BackendGraph 调优（R011–R023）、ShaderPipelineCache（R024）。机器注册了 zen 端点时自动追加 zen 规则 R012–R018（ZenShared 配置正确性，无需加 flag）。带自动备份的一键修复。

R001–R025 base + R012–R018 zen · 3 级 INI · 一键 apply（含 .bak）
$ uecm-cli ini scan --machine-ids 3,4,5 --cred-alias prod
$ uecm-cli ini apply 42 --yes
1b · Health Check

运行可达性

四组垂直体检（共 24 项）：L1 端口（tcp_5985 / tcp_445 / tcp_135）+ L2 Bootstrap（firewall_445 / local_account_token_filter / long_paths_enabled / lanman_server）+ L3 业务（share_reachable / ntfs_perm / cred_user / cred_system / env_vars / env_local / env_shared / system_write / winmgmt / rs_service）+ L3 derived（ini_consistency / pso_precaching / gpu_consistency）+ Zen（zen_reachable / zen_version_consistent / zen_binary_intact / zen_cache_provider_ready，机器没注册 zen 端点时记 na，不计入健康统计）。每行红色状态自带 remediation 文案，告诉操作员下一步该跑哪个 CLI。输出 N 机 × 24 行矩阵。

3 L1 + 4 L2 + 10 L3 + 3 derived + 4 zen · N×24 矩阵 · 每行带 remediation
$ uecm-cli health run --cidr 192.168.10.0/24
$ uecm-cli health run --all --cred-alias prod
$ uecm-cli health results 7
02

开通与授权

winrm cred bootstrap

诊断发现机器还没开通后，把一台从未纳管过的 Windows render node 从「发现」一路带到「可远程操作」。两条路径按机器可达性选，凭据存本机 DPAPI，TD 不用记任何明文密码。开通这一步会一次性把 WinRM、SMB 服务、防火墙、注册表全配好。

preflight 判 Path B 可行性 推 bootstrap（A · USB 或 B · 远程） 一次开通 7 项系统配置（含 SMB 服务）
Path A · USB 一键

零远程依赖

机器从未纳管 / 远程不可达 / 工作组孤岛。

U 盘塞 UECM-Bootstrap.cmd，跑到机器跟前双击。脚本用 fltmc 检测 admin token 后自提升 UAC，不依赖 LanmanServer，避免在 SMB 没启动的机器上陷入 UAC 重启循环。中文 README 带 UTF-8 BOM，防 PowerShell 5.1 mojibake。

Path B · 远程 PsExec

先 preflight 再动手

机器已在线、SMB 445 + RPC 135 通、有本地管理员凭据。

默认 Shallow 零痕迹：tcp_135 / tcp_445 / 挂 ADMIN$ 测 NTLM / 写删探针文件。--probe 切 Deep：真跑一次 PsExec64（写 Event 7045 / 7036），唯一能检出 UAC remote token filter 拦截的方式。verdict=viable 才推 bootstrap。

bootstrap 默认只开 WinRM core，其余 provisioning 按需开。winrm bootstrap 默认启用 WinRM core（PSRemoting + WinRM 服务 + WRM 防火墙 + Network=Private + TrustedHosts）。enable-winrm.ps1 还能配 SMB Server + 445、WMI、LongPaths、ExecutionPolicy=RemoteSigned、HighPerformance、LocalAccountTokenFilterPolicy=1，但这些都是 opt-in 开关，需显式传（render node 全量 provisioning 时一次开齐）。

这一步开的是 SMB「服务」，不是具体共享。bootstrap 把 SMB Server + 445 + LanmanServer 打开，让缓存分发的网络通道就绪；而把某个 DDC 目录开成具体共享（share create），是 ③ DDC 缓存工作流 legacy 路径里的一步。两者别混。

$uecm-cli winrm preflight lanpc --user Administrator --pass-stdin [--probe]
$uecm-cli winrm bootstrap lanpc --user Administrator --pass-stdin

WinRM Bootstrap 内部分解

从「这台机器是空盒子」走到「UECM 能远程跑 PowerShell」的全过程拆开看： 5 个脚本协同 2 条路径，10 个系统修改全部幂等，preflight 输出 4 种判定。 下面每一块都对应 ps-scripts/ 里的真实源码。

1 · 脚本清单 · ps-scripts/
target · 本体
enable-winrm.ps1

目标机本地以管理员身份运行。10 个动作 + 10 个开关，全部幂等，重跑无副作用。

target · 启动器
UECM-Bootstrap.cmd

双击入口，用 fltmc（不依赖 LanmanServer）检测 admin token 后自提升 UAC。

operator · 远程推送
bootstrap-winrm-remote.ps1

主控机用 PsExec64 把 enable-winrm.ps1 拷到目标 ADMIN$ 跑掉，顺手写 operator 端 TrustedHosts。

operator · 体检
preflight-path-b.ps1

主控机侧 5 步可达性检查，输出 viable / likely_viable / blocked / uncertain 四种判定。

build · U 盘包
package-winrm-bootstrap.ps1

把 3 个文件打成可拷 USB 目录。中文 README 用 UTF-8 BOM 单独拷，绕开 PS 5.1 ANSI 重编码乱码。

cli · 入口
uecm-cli winrm <action>

Rust 端 domain_winrm.rs 包了 4 个 action：probe / preflight / bootstrap-script / bootstrap。

2 · enable-winrm.ps1 实际改了什么 · 10 个动作
(默认) WinRM 服务设 Automatic + 启动，跑 Enable-PSRemoting -Force -SkipNetworkProfileCheck 和 winrm quickconfig -q，启用 Windows Remote Management 防火墙规则组（HTTP 5985）。 always
-NetworkCategory Private 把所有 active 网络从 Public 改成 Private，让 WinRM 防火墙规则在公网档不被默拒；传 Skip 跳过。 default on
-AllowedRemoteAddress 1.2.3.4,... 把 Windows Remote Management 防火墙规则的 RemoteAddress 限制成指定 IP / CIDR，只放行 UECM 主控机网段。 opt-in
-TrustedHosts host1,host2 写入本机 WSMan:\localhost\Client\TrustedHosts，让这台机器自己也能反向连别的工作组节点。 opt-in
-EnableLocalAccountRemoteAdmin 设 HKLM:\...\Policies\System\LocalAccountTokenFilterPolicy = 1，让 workgroup 本地 Administrators 组成员远程拿到完整 admin token。域账号场景一般不需要。 opt-in
-EnableSmbServer 把 LanmanServer 设 Automatic 并启动，启用 FPS-SMB-In-TCP 规则（只放 TCP 445，不开整组 File & Printer Sharing 避免多余攻击面）。zh-CN 系统用 rule Name 而非本地化 DisplayName 查找。 opt-in
-EnableWmi 把 Winmgmt 设 Automatic 并启动，UECM 远程查 GPU / UE 版本依赖这个。 opt-in
-SetExecutionPolicy RemoteSigned 在 LocalMachine 作用域设执行策略；被 GPO 锁住时只记 WARNING 不失败。可选 RemoteSigned / Bypass / Skip。 opt-in
-EnableLongPaths 设 HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem\LongPathsEnabled = 1，让 UE 资源路径超过 260 字符不挂。 opt-in
-PowerProfile HighPerformance 激活高性能电源计划。Win11 部分版本会隐藏 HighPerformance GUID，脚本会 powercfg /duplicatescheme 还原并打 UECM-* 标签，重复跑不会每次新建。 opt-in
3 · UECM-Bootstrap.cmd 默认参数

双击入口把所有 opt-in 全开。等价于在管理员 PowerShell 跑：

PS>.\UECM-Bootstrap-WinRM.ps1 ^
    -NetworkCategory Private -EnableLocalAccountRemoteAdmin ^
    -EnableSmbServer -EnableWmi ^
    -SetExecutionPolicy RemoteSigned ^
    -EnableLongPaths -PowerProfile HighPerformance

UAC 自提权细节：用 fltmc >nul 检测 admin token，不是 NET SESSION。后者依赖 LanmanServer，但 LanmanServer 没启动恰恰是 -EnableSmbServer 要修的状态，用 NET SESSION 会陷入 UAC 重启死循环。chcp 65001 强制 UTF-8 控制台保证 JSON 不乱码。

4 · preflight-path-b.ps1 · 5 步可达性检查
1 tcp_135 DCE/RPC Endpoint Mapper 端口。PsExec 走 SCM 必经。不通直接判 blocked。
2 tcp_445 SMB 端口。PsExec 推 service binary 走这里，UECM SMB 共享分发也走这里。
3 admin_share_mount 用传入凭据真挂 \\<host>\ADMIN$。bare 用户名会自动改成 <host>\<user>，强制按目标本地账号认证，不走主控机域。
4 admin_share_write 在 ADMIN$\Temp 写 + 删 probe 文件。删失败仍判 ok，但消息里贴残留路径让人工清理。
5 psexec_probe (opt-in) 需 --probe。真跑 PsExec64 cmd /c exit 0，会在目标写 Event 7045 (service install) + 7036 (service remove)。唯一能检出 UAC remote token filter 拦截的方式。
viable

1–5 步全过，PsExec SCM 探针确认。Path B 可直接推。

likely_viable

1–4 步过，5 跳过。网络 / SMB / ADMIN$ 都通，但没确认 SCM。建议加 --probe 再跑一次。

blocked

1–4 任一失败，或 5 失败（UAC remote token filter 最可能）。改走 Path A USB。

uncertain

主控机本身没有 PsExec64。目标侧无法判断，CLI 也算非零退出，自动化不能继续。

5 · Path B · bootstrap-winrm-remote.ps1 运行机理

从主控机推 enable-winrm.ps1 到目标机的 4 个动作

1 · mount admin$

New-PSDrive 以传入凭据挂 \\<host>\ADMIN$，drive 名用随机 GUID 后缀防冲突。

2 · copy script

Copy-Item 把本地 enable-winrm.ps1 拷到 ADMIN$\Temp\UECM-Bootstrap-WinRM.ps1。

3 · psexec invoke

用 PsExec64 以 SYSTEM (-h 提升) 跑 cmd.exe /c powershell.exe -File %SystemRoot%\Temp\UECM-Bootstrap-WinRM.ps1。

4 · operator trustedhosts

把目标 host / IP 追加进主控机 WSMan:\localhost\Client\TrustedHosts，后续带凭据 WinRM 才能用。

失败模式：finally 块清掉 drive 和 remote 脚本；操作员可以选 --enable-local-admin 把 LocalAccountTokenFilterPolicy 一起改了，给 workgroup 场景免去额外一步。

6 · 部署通道 · 6 种把脚本送到目标机的方式
通道 01 · 推荐

UECM 自动 bootstrap

ADMIN$ + RPC + SCM 全通时直接走。CLI: uecm-cli winrm bootstrap。UECM 用 bundled PsExec64.exe 走 Path B，并把 TrustedHosts 一起写好。

通道 02 · 兜底

USB 一键

远程不可达 / 机器在工作组孤岛。package-winrm-bootstrap.ps1 生成目录，拷 U 盘，目标机双击 UECM-Bootstrap.cmd。

通道 03

共享盘

目标机能访问 NAS / 网盘但主控机管不到。把 USB 包丢上去，让现场人员到目标机本地跑一次。

通道 04

Golden image

机器走统一镜像部署时，把 enable-winrm.ps1 合进 sysprep 后的初始化流程。新机开机即可被 UECM scan。

通道 05

GPO startup script

域环境推荐。GPO 计算机启动脚本下发 enable-winrm.ps1，批量 render node 一次到位。

通道 06

Intune / SCCM / RMM

已有企业设备管理时，把 enable-winrm.ps1 当 remediation script 或 one-shot package 下发。

7 · CLI 命令参考 · uecm-cli winrm
uecm-cli winrm probe <host>
单机 WinRM 端点探测，返回 ok / message / latency_ms。失败时 CLI 非零退出。
uecm-cli winrm preflight <host> --user admin --pass-stdin [--probe]
跑 5 步 preflight。默认 Shallow 零痕迹，加 --probe 切 Deep（写 2 条 Event）。verdict=blocked 或 uncertain 时 CLI 非零退出，避免自动化盲跑下一步。
uecm-cli winrm bootstrap-script [--output setup.ps1]
把 enable-winrm.ps1 的源码原样输出到 stdout 或文件，给现场人员当离线参考 / GPO 输入用。
uecm-cli winrm bootstrap <host> --user admin --pass-stdin [--enable-local-admin]
触发 Path B 远程推送。内部调 bootstrap-winrm-remote.ps1，需要 bundled PsExec64.exe 可达。Workgroup 场景加 --enable-local-admin。
8 · 不会动的东西 · 显式声明
bootstrap 不做以下任何一件事
  • 不开 SSH · UECM 只走 WinRM
  • 不开 Basic auth · 全部 NTLM / Kerberos
  • 不开 CredSSP · 不引入凭据委派
  • 不开 HTTPS 5986 · 只用 HTTP 5985
  • 不设 AllowUnencrypted · WinRM 默认加密
  • 不创建 / 修改用户账号 · 不动密码
  • 不重启机器 · 30 秒内跑完
  • 不装任何软件 · 没有常驻 agent
  • 不动 Defender / EDR · 不放行病毒例外
  • 不改 RDP / 域账号 / 已有共享 · 边界外不碰
9 · 主控机侧首次连接前的一步
workgroup / IP 直连场景需在主控机加 TrustedHosts。 目标机 bootstrap 成功不等于主控机能立刻连过去。WinRM 客户端默认拒绝带凭据连 IP 形式的目标，需要在主控机管理员 PowerShell 下跑一次。 Path B（winrm bootstrap）会自动处理这一步；Path A（USB）跑完后需要手动跑： Set-Item WSMan:\localhost\Client\TrustedHosts ` -Value '192.168.10.50,192.168.10.51' -Force 替换成所有目标机 IP（逗号分隔），或用 192.168.10.* 覆盖整段。只需做一次。
02

SMB 共享配置

share

在目标机上把 DDC 路径开成 SMB 共享，是后面所有缓存分发的物理基础。两种模式按集群信任度选：

Mode A

信任内网

最快上手，适合封闭 VP 棚。

开启 Guest 账户，把目标目录的 NTFS / Share 权限都开成 Everyone : Full。集群内任何机器、任何用户都能直接读写。

Mode B

严格凭据 + SYSTEM 注入

区别于「手撕 net share」的关键能力。

新建本地账号 ddc-svc，把凭据同时写到当前用户 Credential Manager 和 SYSTEM 凭据空间，让 LocalSystem 启动的服务（如 RenderStream Service）也能在无人登录时挂载共享。

选择依据：如果集群里跑了 RenderStream 这类 SYSTEM 服务，必须用 Mode B；否则服务进程拿不到任何用户凭据，路径会被解析为本地不存在。

$uecm-cli share create --host lanpc --mode A
$uecm-cli share inject-system-cred --host lanpc --user ddc-svc
$uecm-cli share list --all

03

DDC 缓存工作流（含 PSO）

ddc zen pso share

机器开通后跑缓存部署——三层缓存的落地。DDC 双 backend（legacy .ddp pak / zen daemon）按 UE 版本二选一；PSO Cache 是同一条流水线的延续，消除切场卡顿。deploy ddc 能把全流程 11 步一键串起来。

3a DDC Backend · legacy / zen 双路径
Legacy · .ddp Pak

文件式共享缓存

UE ≤ 5.3，或 5.4+ 但 zen 不可达时的兜底。

调 UE runner 把工程 DDC 烤成一个 .ddp pak，校验完整性后用 Robocopy 扇出到全集群的 SMB 共享。机器开工程时从共享路径读，不再本地重编译。

Zen · Daemon

引擎原生缓存服务

UE 5.4+ 内置 ZenServer，缓存走 HTTP 不再靠文件扇出。

master 节点跑 ZenServer Windows 服务，worker 工程 INI 指向它的 ZenShared upstream。UECM 管端点注册、/health 探活、服务生命周期、URL ACL 和 INI 切换，不碰 zen 二进制本身。

--backend auto 决策：工程 UE < 5.4 或版本未知 → 走 legacy（保守）；UE ≥ 5.4 且机器装了 5.4+ 引擎、zen 端点可达 → 走 zen（此时 ddc 命令是 no-op，缓存由 zen 原生托管）；否则回落 legacy。每工程每机器的 project_cache_backend 显式覆盖永远赢过这张决策表。

$uecm-cli ddc generate --project-id 7 --source-machine 3 --backend legacy
$uecm-cli ddc verify --project-id 7 --source-machine 3
$uecm-cli ddc distribute --project-id 7 --source-machine 3 --targets 4,5,6 --backend auto --yes

legacy 分发的前置 · SMB 共享创建：把 DDC 目录开成共享有两种模式——Mode A 开 Guest + Everyone:Full（封闭 VP 棚最快上手）；Mode B 建 ddc-svc 账号 + 把凭据注入 SYSTEM 凭据空间（集群里跑 RenderStream 这类 LocalSystem 服务时必须用，否则服务进程拿不到凭据、共享路径会被解析为本地不存在）。zen 模式走 HTTP，不需要这一步。

$uecm-cli share create --mode b --host lanpc --share DDC --local-path D:\UE-DDC --yes
$uecm-cli share inject-system-cred --client-host worker1 --target-host lanpc --svc-user ddc-svc --yes

切到 zen 的典型链路：注册端点 → 探活 → master 装服务 → 集群改 INI 切 ZenShared upstream。

$uecm-cli zen register --machine 3 --declared-port 8558 --role shared_upstream --lifecycle installed_service --data-dir D:\ZenData
$uecm-cli zen probe --all --cred-alias prod
$uecm-cli zen service install --endpoint-id 1 --cred-alias prod --yes
$uecm-cli zen enable --project-id 7 --machines 3,4,5 --upstream-endpoint-id 1 --cred-alias prod --yes
zen 的两条红线。UECM 绝不在 server 端重装 zen 二进制（视作不可信升级，PS sidecar 层硬拦）；zen disable 也只删 ZenShared key，不自动恢复 legacy SMB / Pak 配置。 要回退旧配置，用 git restore 或 ini_editor 留下的 .bak.<timestamp> 兄弟文件。
3b PSO Cache · 切场零卡顿

L2 + L3 缓存。先体检 precaching CVar 配置，再用 UE -game 模式跑采集，得到 *.upipelinecache / *.stablepc.csv，最后带 GPU 一致性检测再分发。

验 R008–R010 precaching CVar UE -game 跑采集 持久化 .upipelinecache / .stablepc.csv GPU 一致性检测后扇出分发
$uecm-cli pso verify --project-id 7
$uecm-cli pso collect --project-id 7 --source-machine 3
$uecm-cli pso distribute --project-id 7 --source-machine 3 --targets 4,5,6 --yes
GPU mismatch 检测必须先过。把 RDNA 上采集的 PSO 推给 Ampere（或反过来）会触发首帧 pipeline 重建，肉眼可见 hitch。pso distribute 内建 GPU preflight guard，不靠 flag 触发。 分发前 UECM 会对比源机和目标机的 GPU vendor / family / driver，不一致直接拒绝。
3c 一键 deploy 编排

deploy ddc --plan 把上面这些（开本地目录 → 建 SMB 共享 → 写 BackendGraph → 生成/分发 pak → 设 PSO CVar → 采集/分发 PSO → 验证启动日志）11 步串成一条工作流，支持 --dry-run 预览和 --stop-on-failure。

$uecm-cli deploy ddc --plan ./deploy-plan.json --dry-run
$uecm-cli deploy ddc --plan ./deploy-plan.json --yes

$uecm-cli log verify-startup --host lanpc --editor-exe "C:\UE\Engine\Binaries\Win64\UnrealEditor-Cmd.exe" --project "D:\Show\My.uproject"
