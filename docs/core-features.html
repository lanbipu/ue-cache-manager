U UE Cache Manager Operator's Manual · Core Functions
UECM · 三层缓存定位

把 UE 工程在多机集群上的
零编译启动、零卡顿运行集中化、自动化、可视化。

面向 VP / XR 渲染集群的 TD 和 IT 运维：5–20 台 Windows render node，操作直接对接拍摄现场。 下面 5 个核心功能覆盖 UECM 的全部主路径；其余 system / winrm / cred / env / gpu / project / 单条 INI 编辑等域是底层支撑，不单独成核心。

L1 · DDC

Derived Data Cache

消除 Shader 重编译，让所有机器开工程时直接读共享缓存。

L2 · PSO Precaching

引擎主动预创建

UE 5.1+ 加载关卡时主动预创建 GPU pipeline state，消除场景切换卡顿。

L3 · PSO Cache 文件

兜底缓存

采集 .upipelinecache / .stablepc.csv，兜底 Precaching 漏掉的边缘组合。

01

机器集群接入与状态刷新

machine winrm cred bootstrap

把一台从未纳管过的 Windows render node，从「发现」一路带到「可远程操作 + 状态可读」。 两条 bootstrap 路径按机器可达性选，凭据存本机 DPAPI，TD 不用记任何明文密码。

扫 CIDR（5985 / 445 / 135） preflight 判 Path B 可行性 推 bootstrap（A · USB 或 B · 远程） machine refresh 读 UE 版本（注册表）+ GPU（WMI）
Path A · USB 一键

零远程依赖

机器从未纳管 / 远程不可达 / 工作组孤岛。

U 盘塞 UECM-Bootstrap.cmd，跑到机器跟前双击。脚本用 fltmc 检测 admin token 后自提升 UAC，不依赖 LanmanServer，避免在 SMB 没启动的机器上陷入 UAC 重启循环。中文 README 带 UTF-8 BOM，防 PowerShell 5.1 mojibake。

Path B · 远程 PsExec

先 preflight 再动手

机器已在线、SMB 445 + RPC 135 通、有本地管理员凭据。

默认 Shallow 零痕迹：tcp_135 / tcp_445 / 挂 ADMIN$ 测 NTLM / 写删探针文件。--probe 切 Deep：真跑一次 PsExec64（写 Event 7045 / 7036），唯一能检出 UAC remote token filter 拦截的方式。verdict=viable 才推 bootstrap。

bootstrap 实际做的 7 件事：不只是开 WinRM。enable-winrm.ps1 默认全开，覆盖 WinRM core、SMB Server + 445、WMI、ExecutionPolicy=RemoteSigned、LongPaths、HighPerformance、LocalAccountTokenFilterPolicy=1，远程操作 / 状态读取 / UE 资源路径所需的整套系统配置一次到位。

$uecm-cli machine scan --cidr 192.168.10.0/24
$uecm-cli winrm preflight lanpc --user admin --pass-stdin [--probe]
$uecm-cli winrm bootstrap --host lanpc
$uecm-cli machine refresh --all
新机接入 30 min → 5 min PRODUCT.md · 成功标准
02

SMB 共享配置

share

在目标机上把 DDC 路径开成 SMB 共享，是后面所有缓存分发的物理基础。两种模式按集群信任度选：

Mode A

信任内网

最快上手，适合封闭 VP 棚。

开启 Guest 账户，把目标目录的 NTFS / Share 权限都开成 Everyone : Full。集群内任何机器、任何用户都能直接读写。

Mode B

严格凭据 + SYSTEM 注入

区别于「手撕 net share」的关键能力。

新建本地账号 ddc-svc，把凭据同时写到当前用户 Credential Manager 和 SYSTEM 凭据空间，让 LocalSystem 启动的服务（如 RenderStream Service）也能在无人登录时挂载共享。

选择依据：如果集群里跑了 RenderStream 这类 SYSTEM 服务，必须用 Mode B；否则服务进程拿不到任何用户凭据，路径会被解析为本地不存在。

$uecm-cli share create --host lanpc --mode A
$uecm-cli share inject-system-cred --host lanpc --user ddc-svc
$uecm-cli share list --all
03

DDC Pak 工作流

ddc L1 缓存层

调 UE runner 生成 .ddp pak，校验文件完整性后用 Robocopy 扇出到全集群。三层缓存里的第一层，消除 Shader 重编译。

UE runner 生成 .ddp pak 验证文件完整性 Robocopy 扇出到全集群
$uecm-cli ddc generate --project MyVPShow --engine 5.5
$uecm-cli ddc verify --pak ./MyVPShow.ddp
$uecm-cli ddc distribute --pak ./MyVPShow.ddp --targets all
04

PSO Cache 工作流

pso L2 + L3 缓存层

先体检 precaching CVar 配置，再用 UE -game 模式跑采集，得到 *.upipelinecache / *.stablepc.csv，最后带 GPU 一致性检测再分发。

验 R008–R010 precaching CVar UE -game 跑采集 持久化 .upipelinecache / .stablepc.csv GPU 一致性检测后扇出分发
$uecm-cli pso verify --host lanpc
$uecm-cli pso collect --project MyVPShow --map MainStage
$uecm-cli pso distribute --source lanpc --targets all --check-gpu
GPU mismatch 检测必须先过。把 RDNA 上采集的 PSO 推给 Ampere（或反过来）会触发首帧 pipeline 重建，肉眼可见 hitch。 分发前 UECM 会对比源机和目标机的 GPU vendor / family / driver，不一致直接拒绝。
05

集群诊断

ini health

两个互补的子模块：一个查配置正确性，一个查运行可达性。组合起来回答「集群健康吗 / 哪里不对 / 怎么修」。

5a · INI Scanner

配置正确性

7 条规则 R001–R007，扫 project / user / engine 三级 INI，找硬编码 DDC Path=、user 级覆盖、mapped drive 路径、deprecated CVar 等问题。 支持带自动备份的一键修复。

7 条规则 · 3 级 INI · 一键 apply（含 .bak）
$ uecm-cli ini scan --host lanpc
$ uecm-cli ini apply-finding --id R003
5b · Health Check

运行可达性

分三层垂直体检（共 17 项）：L1 端口（tcp_5985 / tcp_445 / tcp_135）+ L2 Bootstrap（firewall_445 / local_account_token_filter / long_paths_enabled / lanman_server）+ L3 业务（share_reachable / ntfs_perm / cred_user / cred_system / env_vars / system_write / winmgmt + 3 derived ini_consistency / pso_precaching / gpu_consistency）。每行红色状态自带 remediation 文案，告诉操作员下一步该跑哪个 CLI。输出 N 机 × 17 行矩阵。

3 L1 + 4 L2 + 7 L3 + 3 derived · N×17 矩阵 · 每行带 remediation
$ uecm-cli health run --cidr 192.168.10.0/24
$ uecm-cli health run --all --cred-alias prod
$ uecm-cli health results --format matrix
底层支撑（不单独成核心）

下面这些域是上面 5 个核心功能能跑起来的「水电煤」：单独看不构成完整业务，但每个 CLI / GUI 操作都会经过它们。出问题时 health 矩阵会先点出来。
