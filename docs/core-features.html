U UE Cache Manager Operator's Manual · Core Functions
UECM · 三层缓存定位

把 UE 工程在多机集群上的
零编译启动、零卡顿运行集中化、自动化、可视化。

面向 VP / XR 渲染集群的 TD 和 IT 运维：5–20 台 Windows render node，操作直接对接拍摄现场。 下面 3 个核心功能按操作顺序覆盖 UECM 的主路径：① 状态刷新与集群诊断（先看清现状）→ ② 开通与授权（让机器可被远程管，统一走 SSH key 认证）→ ③ DDC 缓存工作流（含 PSO，缓存落地）。其余 system / ssh / secret / env / gpu / project / 单条 INI 编辑等域是底层支撑，不单独成核心（winrm 命令域 + DPAPI 在迁移后退役中）。

L1 · DDC

Derived Data Cache

消除 Shader 重编译。两条 backend：legacy .ddp pak（UE ≤ 5.3）与 zen daemon 原生缓存（UE 5.4+），由 ddc --backend auto 自动路由。

L2 · PSO Precaching

引擎主动预创建

UE 5.1+ 加载关卡时主动预创建 GPU pipeline state，消除场景切换卡顿。

L3 · PSO Cache 文件

兜底缓存

采集 .upipelinecache / .stablepc.csv，兜底 Precaching 漏掉的边缘组合。

  1. 01 状态刷新与集群诊断
  2. 02 开通与授权
  3. 03 DDC 缓存工作流（含 PSO）

开测前准备 · 从零到第一条命令

下面 3 个功能的命令默认你环境已就绪。第一次从零开始,先按这 4 步把"料"备齐(只做一次),后面的命令才能跑通。命令都在 lanPC 的 PowerShell 里跑(mac 上除 scan / list 外全报 Windows-only)。

0

让 uecm-cli 全局可用(只做一次)

在 lanPC PowerShell 跑下面这行,然后关掉重开一个窗口;之后任意目录直接敲 uecm-cli,本页命令复制即跑,不用加 .\。

$[Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path","User").TrimEnd(';') + ";C:\Tools\UECM", "User")
1

把"要管的"机器加进库(scan 看全部,add 才选)

scan 会列出网段里所有在线机器(路由器 / NAS / 办公机都在内),但它不写库;你只 add 真正要部署的 Windows 渲染节点——NAS、路由器、Linux、普通办公 PC 不用加。add 给机器一个数字 id,list 看 id(后面 refresh / ini / health 全用这个 id,不是 IP)。

判断:scan 探的是 5985 / 445 端口(发现层暂沿用,见说明),先 add 进库;真正能被 UECM 远程操作要 onboard SSH(双击 .cmd,见功能 02)——onboard 后用 ssh probe 确认。加错了用 machine delete <id> --yes 删掉。

$uecm-cli machine scan 192.168.10.0/24
$uecm-cli machine add --ip 192.168.10.20
$uecm-cli machine list
2

onboard SSH(装好就不用再管凭据)

UECM 走 SSH key 认证:目标机双击纳管包里的 UECM-Bootstrap.cmd(装 OpenSSH + 建 uecm-svc + 授权公钥,见功能 02),之后 refresh / ini / health / zen / share / deploy 都不用传任何凭据——key 认证统一用 uecm-svc。用 ssh probe 确认连通。

$uecm-cli ssh probe 192.168.10.20

只有仍走 WinRM/PsExec 的 machine authorize(legacy,退役中)才真用凭据;那时用 cred save 存一个别名(密钥进跨平台 SecretStore,不再 cmdkey/DPAPI):

$"UecmRender@2026" | uecm-cli cred save --alias render --user uecm-svc --pass-stdin --kind winrm
备齐这 3 步,下面 3 个核心功能的命令就能照着跑了——id 用 machine list 里的数字;SSH 命令不用带凭据。

怎么读下面的命令注解

每条 uecm-cli 命令下方给三行:功能(它做什么)、作用(在流程里干嘛)、UI(这操作在前端对应哪个 invoke 命令函数)。UI 行只标 commands::模块::函数——这是前后端对应的硬锚点(将来哪个按钮点了就 invoke 它);按钮的中文文案以最终 UI 设计为准,这里不写死。

标 ✗ 仅 CLI 的命令:UI 还没暴露(没注册到 invoke_handler),只能命令行跑。目前是这几条:health run --cidr 直扫网段、ssh probe、secret set/get/list/delete、zen enable / zen disable。

认证模型 · SSH key(uecm-svc):节点传输统一用 uecm-svc 的 SSH key,refresh / ini / health / zen / share / deploy 等命令不需要 operator 凭据。--cred-alias / --user --pass 仍接受但被忽略(向后兼容 shim);只有仍走 WinRM/PsExec 的 machine authorize(legacy)真用它们。旧的 --auth-method flag 已随 WinRM 迁移移除。

machine ini health

02

开通与授权

ssh secret cred

诊断发现机器还没开通后，把一台从未纳管过的 Windows render node 从「发现」一路带到「可远程操作」。UECM 所有远程操作走 SSH key 认证：开通就是在目标机装好 OpenSSH、建统一运维账号 uecm-svc、把 UECM 的公钥授权进去，顺手把 SMB 服务、WMI、注册表全配好。主路径是双击一个 .cmd，TD 不用记任何明文密码；密钥只在主控机本地的 SecretStore（AES-GCM，跨平台）里。

双击 UECM-Bootstrap.cmd enable-ssh.ps1 一次开通（OpenSSH + uecm-svc + 授权公钥 + SMB/WMI/...） ssh probe 确认 uecm-svc key 连得上
主路径 · USB / 共享盘一键

零远程依赖

机器从未纳管 / 远程不可达 / 工作组孤岛 —— 也是当前推荐的统一纳管姿势。

把 package-winrm-bootstrap.ps1 生成的包（含 UECM-Bootstrap.cmd + enable-ssh.ps1 + uecm.pub + PsExec64.exe）拷到机器跟前双击。脚本用 fltmc 检测 admin token 后自提升 UAC（不依赖 LanmanServer，避开 SMB 没启动时的 UAC 重启死循环）。SSH onboarding 成败计入退出码——缺 uecm.pub 或 enable-ssh 失败时 .cmd 直接报 FAILED，不会假成功。.cmd 必须 CRLF + 纯 ASCII，中文只放 README。

Deep dive · F02 子系统

SSH Onboarding 内部分解

从「这台机器是空盒子」走到「UECM 能以 uecm-svc 跑远程 PowerShell」的全过程拆开看： 双击一个 .cmd → enable-ssh.ps1 把节点准备到「SSH 连得上 + 渲染可用」，所有系统修改幂等。 下面每一块都对应 ps-scripts/ 里的真实源码。

1 · 脚本清单 · ps-scripts/
target · 本体
enable-ssh.ps1

目标机本地以管理员身份运行。装 OpenSSH、建 uecm-svc 本地管理员、把 uecm.pub 授权进 administrators_authorized_keys，再开 SMB/WMI/LongPaths/ExecutionPolicy/HighPerformance，全部幂等。

target · 启动器
UECM-Bootstrap.cmd

双击入口，用 fltmc（不依赖 LanmanServer）检测 admin token 后自提升 UAC。跑完把 SSH onboarding 退出码计入成败（缺 uecm.pub / 失败即报 FAILED）。

build · 纳管包
package-winrm-bootstrap.ps1

把 .cmd + enable-ssh.ps1 + uecm.pub + PsExec64.exe 打成可拷目录。-UecmPublicKeyPath 现在必填，不再产出无 SSH 的包。中文 README 用 UTF-8 BOM 单独拷，绕开 PS 5.1 乱码。

cli · 入口
uecm-cli ssh <action>

Rust 端 domain_ssh.rs：probe（uecm-svc key 探测）。package-bootstrap / authorize 在 P5a 补齐（一并退役 winrm 域）。

cli · 密钥
uecm-cli secret <action>

domain_secret.rs：set / get / list / delete，直管跨平台 SecretStore（AES-GCM）。

legacy · 退役中
enable-winrm.ps1 · winrm 域

enable-winrm.ps1 / bootstrap-winrm-remote.ps1 / preflight-path-b.ps1 + uecm-cli winrm 是迁移前的 WinRM 路径，P0–P4 仍在但已非主路径，P5a 删。

2 · enable-ssh.ps1 实际改了什么 · 默认 + opt-in
(默认) 装 OpenSSH.Server capability，把 sshd + ssh-agent 设 Automatic 并启动，加 OpenSSH-Server-In-TCP 防火墙规则（TCP 22）。 always
(默认) 把 UECM 公钥（uecm.pub，默认从 -StagingSourceDir 取）授权进 C:\ProgramData\ssh\administrators_authorized_keys——这是 Windows OpenSSH 对本地管理员统一用的授权文件,所以 uecm-svc 必须是 admin。 always
(默认) 把同目录的 *.ps1 节点脚本 + PsExec64.exe stage 到 C:\ProgramData\UECM，供 UECM 经 SSH -File 调用（消除命令行长度风险）。 always
-CreateLocalAdmin -LocalAdminName uecm-svc -LocalAdminPassword … 建本地管理员账号 uecm-svc（SshExecutor 永远以它登录）+ 加入 Administrators。强制只接受 uecm-svc——传别的名直接 throw（避免报 ready 但 UECM 连不上的错配）。 .cmd 默认开
-EnableSmbServer 把 LanmanServer 设 Automatic 并启动，启用 FPS-SMB-In-TCP 规则（只放 TCP 445）。缓存分发走 SMB,依赖这个。 opt-in
-EnableWmi 把 Winmgmt 设 Automatic 并启动，UECM 远程查 GPU / UE 版本依赖这个。 opt-in
-SetExecutionPolicy RemoteSigned 在 LocalMachine 作用域设执行策略；被 GPO 锁住时只记 WARNING 不失败。可选 RemoteSigned / Bypass / Skip。 opt-in
-EnableLongPaths 设 HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem\LongPathsEnabled = 1，让 UE 资源路径超过 260 字符不挂。 opt-in
-PowerProfile HighPerformance 激活高性能电源计划。Win11 隐藏 HighPerformance GUID 时 powercfg /duplicatescheme 还原并打 UECM-* 标签，重复跑不新建。 opt-in
readiness gate（结束时硬判） ok = OpenSSH capability 装好 + sshd 在跑 + 公钥已授权 + uecm-svc 存在 + 启用 + 在 Administrators（无条件校验,连 -CheckOnly 也查）。任一不满足判 not ready,.cmd 据此报成败。 always
3 · UECM-Bootstrap.cmd 默认参数

双击入口跑两段（迁移期并存）：先 enable-winrm.ps1（legacy，退役中），再 enable-ssh.ps1（主路径）。SSH 段等价于在管理员 PowerShell 跑：

PS>.\enable-ssh.ps1 ^
    -PublicKeyPath .\uecm.pub -StagingSourceDir . ^
    -CreateLocalAdmin -LocalAdminName uecm-svc -LocalAdminPassword … ^
    -EnableSmbServer -EnableWmi ^
    -SetExecutionPolicy RemoteSigned -EnableLongPaths -PowerProfile HighPerformance

成败计入 SSH：OVERALL = PS_EXIT==0 AND SSH_EXIT==0。enable-ssh 退出码在顶层捕获（避开 cmd 延迟展开陷阱）；缺 enable-ssh.ps1 或 uecm.pub 时 SSH_EXIT=9 → 直接 FAILED，不再像迁移前那样只看 WinRM 退出码假成功。SSH_ADMIN_ARGS 里 -LocalAdminName 硬编码 uecm-svc（与 WinRM local-admin 名独立）。 UAC 自提权：用 fltmc >nul 检测 admin token（不依赖 LanmanServer，避开 UAC 重启死循环）。 .cmd 必须 CRLF + 纯 ASCII，中文只放 README，否则双击报 'xxx' is not recognized 乱码且账号不建。

4 · SSH key 认证模型 · uecm-svc
1 keypair 主控机首次用时自动生成 uecm_ed25519 密钥对（私钥留本机）；公钥 uecm.pub 随纳管包明文下发。
2 authorized_keys enable-ssh 把 uecm.pub 写进目标机 C:\ProgramData\ssh\administrators_authorized_keys——Windows OpenSSH 对本地管理员统一用这个文件，所以 uecm-svc 必须是 admin。
3 login = uecm-svc SshExecutor 永远 ssh uecm-svc@<host>（key auth,无密码）。uecm-svc 是本地管理员,所以 admin-required 节点脚本（service install / urlacl / setx）能跑。
4 -File staging 节点脚本不走命令行,先 stage 到 C:\ProgramData\UECM,再 ssh … powershell -File + stdin JSON 喂参（secret 不进进程列表 / 不受命令行长度限制）。
5 loopback operator 自指（localhost）也走真 SSH-to-self uecm-svc（admin 上下文）;distribute 的 robocopy 有本地快路径。所以 operator 本机也要被 onboard（ssh uecm-svc@localhost 通）。

密钥 / known_hosts 由 core/ssh.rs 的 SshExecutor::from_config 管;keepalive（ServerAliveInterval）已加,撑 verify-rules / service-install 这类长任务的单会话。

5 · legacy · WinRM 远程推送（P5a 退役）

迁移前的 Path B —— 现在不是主路径，仅作过渡

machine authorize / winrm bootstrap 用 bundled PsExec64 把 enable-winrm.ps1 远程推到目标 ADMIN$ 跑掉（preflight-path-b.ps1 先做 5 步可达性判定）。这条路径只开 WinRM、不装 SSH key——用它纳管的机器在 refresh / 各 SSH 化命令里会立刻不可达。

处置：P5a 删 core/winrm.rs / domain_winrm / core/bootstrap.rs / preflight / enable-winrm.ps1 等,并把 bootstrap_winrm / get_winrm_bootstrap_script Tauri 命令 repoint 成「用 .cmd 走 SSH」的提示（保持 Vue 兼容形状）。SSH 纳管请走 §3 的 .cmd。

6 · 部署通道 · 把纳管包送到目标机的方式
通道 01 · 推荐

USB / 共享盘一键

WinRM 远程自动推

通道 03

共享盘

目标机能访问 NAS / 网盘但主控机管不到。把纳管包丢上去，让现场人员到目标机本地双击一次。

通道 04

Golden image

机器走统一镜像部署时，把 enable-ssh.ps1（带 uecm.pub）合进 sysprep 后的初始化流程。新机开机即可被 UECM scan + ssh probe。

通道 05

GPO startup script

域环境推荐。GPO 计算机启动脚本下发 enable-ssh.ps1 + uecm.pub，批量 render node 一次到位。

通道 06

Intune / SCCM / RMM

已有企业设备管理时，把 enable-ssh.ps1 当 remediation script 或 one-shot package 下发（公钥随包）。

7 · CLI 命令参考 · uecm-cli ssh / secret
uecm-cli ssh probe <host>
以 uecm-svc key 探目标机 SSH 可达性，返回 ok / message / latency_ms（字段兼容旧 winrm probe）。失败时 CLI 非零退出。替代退役中的 winrm probe。 → UI 无(仅 CLI)
uecm-cli secret set <alias> [--value v | stdin] · get · list · delete
直管跨平台 SecretStore（AES-GCM）。set 从 --value 或 stdin 读；get 打印明文；list 只列别名；delete 带 --yes / --dry-run。 → UI 无(仅 CLI)
uecm-cli cred save --alias a --user u --pass-stdin --kind winrm|share
把 (user, password) 存成可被 --cred-alias 引用的 alias：密钥进 SecretStore（跨平台，不再 cmdkey/DPAPI），元数据进 SQLite。 → commands::credentials::save_credential
uecm-cli winrm probe / bootstrap …
legacy WinRM 命令域,P0–P4 仍在但已非主路径,P5a 退役。→ commands::bootstrap::*（P5a repoint 成 SSH 提示）
8 · 不会动的东西 · 显式声明
SSH onboarding 不做以下任何一件事
  • 不开 password 登录 · 只 key auth（uecm-svc）
  • 不动 sshd 端口 · 标准 TCP 22
  • 不放任意公钥 · 只授权 UECM 自己的 uecm.pub
  • 不创建非 uecm-svc 账号 · 传别的名直接拒绝
  • 不开 HTTPS / CredSSP / Basic · 这些是 WinRM 的事
  • 不重启机器 · 装 OpenSSH capability 即生效
  • 不装常驻 agent · 只 OpenSSH Server（Windows 内置 capability）
  • 不动 Defender / EDR · 不放行病毒例外
  • 不改 RDP / 域账号 / 已有共享 · 边界外不碰
  • 不把私钥下发到节点 · 私钥只在主控机
9 · 主控机侧首次连接前的一步
主控机自身要有 uecm 密钥对,且 operator 若自指要被 onboard。 私钥（uecm_ed25519）由 SshExecutor::from_config 首次用时在主控机本地生成,公钥就是随纳管包下发的 uecm.pub——不用手动配 TrustedHosts/known_hosts。 但 operator 自己也是一台节点时（在本机跑针对 localhost 的 refresh / zen / deploy）,loopback 现在走真 SSH-to-self,需要本机也被 onboard: ssh uecm-svc@localhost # 应免密连通 不通的话,在本机也双击一次 UECM-Bootstrap.cmd 即可。
03

DDC 缓存工作流（含 PSO）

ddc zen pso share

机器开通后跑缓存部署——三层缓存的落地。DDC 双 backend（legacy .ddp pak / zen daemon）按 UE 版本二选一；PSO Cache 是同一条流水线的延续，消除切场卡顿。deploy ddc 能把全流程 11 步一键串起来。

3a DDC Backend · legacy / zen 双路径
Legacy · .ddp Pak

文件式共享缓存

UE ≤ 5.3，或 5.4+ 但 zen 不可达时的兜底。

调 UE runner 把工程 DDC 烤成一个 .ddp pak，校验完整性后用 Robocopy 扇出到全集群的 SMB 共享。机器开工程时从共享路径读，不再本地重编译。

Zen · Daemon

引擎原生缓存服务

UE 5.4+ 内置 ZenServer，缓存走 HTTP 不再靠文件扇出。

master 节点跑 ZenServer Windows 服务，worker 工程 INI 指向它的 ZenShared upstream。UECM 管端点注册、/health 探活、服务生命周期、URL ACL 和 INI 切换，不碰 zen 二进制本身。

--backend auto 决策：工程 UE < 5.4 或版本未知 → 走 legacy（保守）；UE ≥ 5.4 且机器装了 5.4+ 引擎、zen 端点可达 → 走 zen（此时 ddc 命令是 no-op，缓存由 zen 原生托管）；否则回落 legacy。每工程每机器的 project_cache_backend 显式覆盖永远赢过这张决策表。

$uecm-cli ddc generate --project-id 7 --source-machine 3 --backend legacy
$uecm-cli ddc verify --project-id 7 --source-machine 3
$uecm-cli ddc distribute --project-id 7 --source-machine 3 --targets 4,5,6 --backend auto --yes
uecm-cli ddc generate --project-id <id> --source-machine <id> --backend legacy
