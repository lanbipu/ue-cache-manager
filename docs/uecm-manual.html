FEATURE MANUAL · MODULE BREAKDOWN

功能介绍

按依赖分层列出 v1.0 已交付的全部能力。每个模块标注作用域（单机 / 集群 / 跨机分发）， 交付状态，与底层用到的 Windows 通路。 阅读这段时请把它当一份"操作员能力卡片"，而不是 changelog——changelog 见尾部 spec sheet。

M01 BASE LIVE

机器清单与发现 Machine Inventory

CIDR · WinRM · SMB · WMI

从一段 CIDR 起步，扫端口（WinRM 5985 / SMB 445），把可达 Windows 主机持久化到本地 SQLite， 并刷新它们的 UE 安装列表、GPU 型号、驱动版本、显存容量、在线状态。每台机器都有可见的"上次见过时间"。

能做
CIDR 扫描 · 单机刷新 · hostname 重命名 · 多机选中后批量操作 · live online/offline 徽标
怎么读 GPU
显示类注册表 qwMemorySize（绕过 WMI AdapterRAM 的 4 GB 上限，RTX 3080 正确读到 10240 MB）
持久化
machines · machine_ue_installs · machine_gpus
边界
GPU 探测失败时 UE 列表仍保留；非 Windows 主机标"不适用"
M02 BASE LIVE

凭据管理与注入 Credential Aliases

DPAPI · cmdkey · SQLite

一份别名对应一份用户名+密码，密码用 DPAPI 加密落到 %LOCALAPPDATA%\UECM\creds.bin。 每次 WinRM 调用按需解出，转交给 Invoke-Command -Credential； SMB 侧用 cmdkey 做透明认证。UECM 自身无需以管理员身份启动。

UI 入口
机器详情面板 · SMB 共享向导内嵌选择器
注入点
每次 WinRM 远程调用 · cmdkey 用户级 · PsExec64 SYSTEM 级（B 模式共享必备）
SQLite
credentials（别名映射，不存密码）
M03 SHARING LIVE

SMB 共享向导 SMB Share Wizard

Mode A / Mode B · PsExec

一键起一个共享 DDC 盘。两种工作模式： A 模式用 Guest + Everyone:Full，封闭剧组现场友好； B 模式在 Host 上创建 ddc-svc 本地账户，共享只授权给它，再通过 vendor 里的 PsExec64 把该账户凭据以 SYSTEM 身份注入到客户端 —— 这就是为什么 RenderStream Service 也能挂上这块盘。

关键脚本
ps-scripts/ 里 setup-share-mode-* · inject-system-credential
客户端不动用户账
每台机器原有的日常账号继续登录，只多注入一组 Service-Account 凭据
预览即契约
执行前必看 PowerShell 命令明文，无黑盒
M04 CONFIG LIVE

环境变量与 INI 写入 Cluster Config Writes

setx /M · INI atomic write · backup

单机编辑系统级环境变量、单机编辑项目/用户/引擎 INI 键值，都带自动备份。 多机批量推送时一台失败不阻塞其他 —— 通过 mpsc fan-out + Tauri batch-progress 事件 把每台机器的 ✓ / ✗ / ↻ 实时回馈到 UI，最高并发 8 台。

UI 视图
机器列表（批量环境变量 / 批量 INI 入口）· 机器详情面板
原子写
每次写 INI 前自动 snapshot 到 operations.snapshot_blob，可回滚
并发上限
8 台 / 批，避免局域网压垮
M05 DIAGNOSTICS LIVE

INI 扫描器 INI Scanner · R001–R007

Pure Rust rule engine

跨集群扫描项目 / 用户 / 引擎三级 INI 文件，纯 Rust 规则引擎挑出 7 类问题。 UI 用 3 列诊断面板呈现：What（命中规则）、Why（背后机理）、Symptom（用户会看到的现象）， 配合 UecmCodeBlock 的 before/after diff 一键应用。

R001
硬编码 Path=，无 EnvPathOverride 兜底
R002
用户级 DDC 覆盖（EditorPerProjectUserSettings.ini 的隐形杀手）
R003
映射盘符路径 —— Windows Service 起不来时不可达
R004
已弃用的 CVar / ini key
R005
关键环境变量缺失
R006
INI 与环境变量不一致
R007
健康路径基线（命中即"全 OK"）

<ProjectDir>/DerivedDataCache/Compressed.ddp

M08 ARTIFACT LIVE

PSO Cache 工作流 PSO Collect, Verify, Distribute

UE -game · GPU signature

PSO Cache 的整套流水线：先校验 PSO Precaching 三个核心 CVar（R008–R010），再启动 UE -game 模式做现场采集，把 *.upipelinecache / *.stablepc.csv 收回来。 分发时跨机比对 GPU 型号与驱动版本，签名不一致会卡死 —— PSO 是 GPU/驱动强绑定的，混用会比没用还糟。

CVar 校验
r.PSOPrecaching=1 · r.PSOPrecache.Compile=1 · 其他相关项（健康检查 R008–R010）
采集位置
<ProjectDir>/Saved/CollectedPSOs/
GPU 守门
分发前比对 machine_gpus，不一致即 abort 并给出受影响机器列表
UI
PSO Cache 视图 · 文件浏览器 + GPU 矩阵

02
VERIFICATION RUNBOOKS · OPERATOR-PACED

流程说明

每条都是一份可执行的验证 runbook：先看前置条件，再按编号步骤过一遍，最后检查输出。 预览即契约：所有写操作都先展示明文 PowerShell，再实际跑。 失败时按"诊断 + 影响 + 建议修复"三段式读错误面板。

F1 BOOTSTRAP

首次接入一台 Windows 目标

VERIFIED

目标机是裸 IP / 工作组，没接过 UECM。这是"从零到清单可见"的最短路径。

  1. 在目标机上启用 WinRM
    操作端把 docs/bootstrap/enable-psremoting.ps1 拷贝过去，管理员 PowerShell 跑一次。 输出末尾应看到 WinRM listener: HTTP on 0.0.0.0:5985。
  2. 在操作机配置 TrustedHosts
    操作机管理员 PowerShell： 
    # 用 IP 或 hostname 都可，逗号分隔，* 通配仅限内网
winrm set winrm/config/client '@{TrustedHosts="192.168.10.*"}'
  3. UECM 里新建凭据别名
    进入机器列表 → 共享 → 凭据，填本地账户名+密码，起一个易记别名（推荐 ops-admin）。 密码进 DPAPI 加密文件，不进 SQLite 明文。
  4. 扫描 CIDR 添加目标
    机器列表 → 扫描，填 192.168.10.0/24（或目标所在网段）。 扫描完会列出端口可达主机，勾选目标机，点"添加并刷新"。
  5. 观察刷新结果
    通过即表示这台机器在册：UE 安装列表 / GPU 型号 / 驱动版本 / 显存 / hostname 都应被填上。last_seen_at 显示"刚刚"。
FAIL

如果 WinRM 探测红灯但 SMB 绿灯：说明端口可达、PSRemoting 未启。回到第 1 步重新跑脚本，检查目标机防火墙规则。

如果两者都红灯：先 nc -z -w5 <ip> 5985 验网络层，可达后再排查目标机服务状态。

F2 SHARING

建一块 Mode B 的 SMB 共享 DDC

VERIFIED · LOCAL

B 模式才能让 RenderStream Service / 其他 SYSTEM 上下文进程读到共享盘。A 模式只在封闭剧组现场用。

  1. 指定一台 Host
    通常是 NAS 或一台 NTFS 大盘的机器。进入机器列表选中目标 Host，点"创建 Shared DDC"。
  2. 选 Mode B + 路径
    向导选 Mode B，填本地路径（例如 D:\UE-DDC）和共享名（例如 ue-ddc）。 UECM 会生成一个 24 位强随机密码绑给 ddc-svc 账户，密码进 DPAPI。
  3. 看预览
    向导会列出将在 Host 上执行的全部 PowerShell：New-LocalUser、New-SmbShare、 ACL 设置、cmdkey 配置。明文可读，无任何隐藏写。
  4. 选客户端 + 注入 SYSTEM 凭据
    勾选所有 Render Node。对每台机器，UECM 用 vendor/PsExec64.exe -s 把 ddc-svc 凭据写到 SYSTEM 帐户的 cmdkey 域。 进度面板每台机器 ✓/✗/↻ 实时刷新。
  5. 在客户端验证 SYSTEM 可读
    客户端跑： 
    PsExec64.exe -s -i powershell.exe
# SYSTEM 上下文里：
Test-Path \\<host>\ue-ddc
    返回 True 即说明 RenderStream 启动 UE 时也能读到。
F3 DIAGNOSE

跑一遍 INI 扫描 + 一键修复

VERIFIED

典型场景：怀疑某台机器 DDC 静默失效（路径看着对，UE 仍在重编 shader）。INI 扫描器会 7 条规则全过一遍。

  1. 进入 INI 扫描视图
    侧边栏 INI 扫描。选定目标机器（一台或多台），选定项目，点"开始扫描"。
  2. 读结果层级
    结果按项目 / 用户级 / 引擎级三层展开。红色高危先看 —— 大概率是 R002（EditorPerProjectUserSettings.ini 里有用户级覆盖压过了环境变量）。
  3. 看 3 列诊断面板
    点中某条 finding，右侧展开 What / Why / Symptom。底部 UecmCodeBlock 给出 before/after diff。
  4. 一键应用
    点"应用建议"。UECM 自动 snapshot 该 INI 文件到 operations.snapshot_blob， 然后原子写入新内容。失败可一键回滚。
  5. 再扫一遍确认
    修复后立即重新扫一次，应只剩 R007（健康路径基线）—— 也就是全绿。
F4 BATCH

集群批量推送一条环境变量

VERIFIED

把 UE-SharedDataCachePath 一次性写到所有 Render Node 的系统级环境变量。

  1. 机器列表多选
    筛选出所有 Render Node（按 role 标签），点"批量环境变量"。
  2. 填变量名/值 + 选凭据别名
    name  = UE-SharedDataCachePath
value = \\nas01\ue-ddc
scope = Machine
creds = ops-admin
  3. 看预览 → 执行
    预览页给出每台机器要跑的 setx /M 命令。点"执行"后 UI 切到实时进度面板，最高并发 8 台。
  4. 读进度
    [↻] node-01  setx /M ...
[✓] node-02  ok · 84 ms
[✓] node-03  ok · 91 ms
[✗] node-04  WinRM auth failed · retry available
    失败项不阻塞其他，可单独"重试该机器"。
F5 ARTIFACT

DDC Pak 生成 → 分发

PARTIAL · lanPC E2E DEFERRED

组合 2 是核心场景：在一台开发机上做完工程，本机生成 .ddp，再分发到所有渲染节点。 路径映射会自动从 project_locations 复用。本地路径已联通；lanPC 真机 E2E 因 192.168.10.20 不可达暂缓。

  1. 选项目 + 选生成机
    DDC Pak 视图 → 选定项目 → 选定要在哪台机器上执行 -run=DerivedDataCache。
  2. 触发生成
    UnrealEditor.exe Project.uproject \
  -run=DerivedDataCache -fill -DDC=CreatePak
    UECM 监听 UE 日志，必要时可中断。完成后产物在 <ProjectDir>/DerivedDataCache/Compressed.ddp。
  3. 校验 .ddp
    UI 显示文件大小、生成时间、SHA。若校验失败，"重试"按钮重新跑 UE runner。
  4. 选目标节点 + 分发
    勾选要接收的渲染节点。UECM 自动从 project_locations 解析每台机器上该项目的实际路径， Robocopy 多机并发推送。失败项各自重试。
F6 ARTIFACT

PSO Cache 采集 + 分发（带 GPU 守门）

PARTIAL · lanPC E2E DEFERRED

PSO 与 GPU/驱动强绑定 —— 混用会比没用更糟。这条 runbook 把"守门 → 采集 → 分发"串起来。

  1. 先看 GPU 一致性矩阵
    PSO Cache 视图顶部就是 GPU 矩阵。所有目标节点 GPU 型号 + 驱动版本必须一致才进入下一步。 不一致：先升驱动到统一版本，或为不同 GPU 单独采集。
  2. 校验 PSO Precaching CVar
    健康检查里的 R008–R010 是否都绿？r.PSOPrecaching=1 等没开就不会做引擎自动 precache。 未开 → 用 INI 一键修复 / 批量推送补上。
  3. 选定一台采集机 + 远程启动 -game
    UnrealEditor.exe Project.uproject -game \
  -r.ShaderPipelineCache.Enabled=1 \
  -windowed -resx=1920 -resy=1080
    v1.0 仍需操作员或现场人员手动遍历场景（自动摄像机巡游在 v1.1 路线图）。
  4. 采集产物落盘
    <ProjectDir>/Saved/CollectedPSOs/ 下会出现 *.upipelinecache / *.stablepc.csv。 UECM 同时把 GPU 签名写入 pso_cache_files，供后续守门用。
  5. 分发
    选目标节点，UECM 再次比对 GPU 签名。一致 → Robocopy 推送；不一致 → 直接 abort 并列出受影响机器。
F7 HEALTH

跑一遍集群健康检查

VERIFIED

上线前 / 重大变更后必跑。11 行 × N 机器全绿才算 ready。

  1. 进入健康检查视图
    侧边栏 健康检查。默认列出全部在册机器。可按 role 过滤。
  2. 点"运行检查"
    每台机器一次 PowerShell 往返跑完 8 项活检；3 项派生检查基于上一次的 INI 扫描结果与 machine_gpus 数据即时算出。
  3. 看矩阵 + 详情面板
    红格点开 → What / Symptom / How-to-fix + 该项最后一次探测的原始输出。重点关注 cred_system 和 system_write 两列。
  4. 修复 + 重跑
    每条 fix 都对应一个具体动作（重新注入 SYSTEM 凭据 / 改 INI / 补环境变量 / 升驱动）。改完再点一次"运行检查"。

ROADMAP · WHAT'S NEXT

未来规划

v1.0 把"零编译启动 + 零卡顿运行"的工程闭环跑通了。下一阶段的事分三档： NOW（v1.1 候选，已有明确触发条件）· NEXT（v1.2 探索，有方向但需 PoC）· LATER（远期，仍属构想，未冻结优先级）。

NOW · v1.1 触发：lanPC 192.168.10.20 重新可达

lanPC 真机 E2E 全链路通验

F5 / F6 真实 UE 工程跑通：DDC Pak 生成→分发→.ddp 完整性、PSO 采集→GPU 守门→分发→运行时无卡顿验证。本地步骤都过了，缺一次现场拉满的端到端。

可导出的集群报告

把当前这份手册的逻辑做进产品：一键导出本次 Health Check + INI Scan + GPU 矩阵的 PDF/HTML 快照，供项目导演/拍摄团队签收。

Robocopy 失败可断点续传

当前只有重试整次。大工程的 DDC Pak 文件几个 GB 起，中断重传成本高，要做 chunked + resumable。

NEXT · v1.2 需 PoC · 不阻塞当前发布

自动化 PSO 摄像机巡游

v1.0 还要操作员手动遍历场景，效率低且易遗漏。下一步用 UE 自动相机路径脚本驱动 -game 模式，让 PSO 采集变成"启动→等结束"。

多机分布式 PSO 采集

一个项目的关卡列表分片，多台开发机各采一部分，最后合并产物。前提是这些机器 GPU 一致。

AMD / Intel GPU E2E 校验

v1.0 NVIDIA 是唯一已验证路径。AMD/Intel 卡的 PSO 行为与驱动注册表布局有差异，需要现场机器实测覆盖。

定时自动健康检查

建议下限 5 分钟一次，写入 health_check_runs 历史，触发阈值告警（例如关键凭据丢失）。

LATER · v2.x 未冻结 · 视现场反馈再上

多用户协作与 RBAC

当前是单操作员模型，没有审计层。多用户接入后需要操作历史署名、角色（操作员 / 观察员 / 管理员）权限分级。

ZenServer 后端支持

v1 只支持 Filesystem 共享 DDC。ZenServer 是 UE 5.4+ 推的新缓存后端，跨现场带宽场景下更合适，但部署比 SMB 重。

UECM 的 RenderStream 深度联调

把 RenderStream Service 的健康指标也纳入矩阵：服务运行状态、当前挂载盘、最近一次 UE 启动日志摘要。让"服务起不来"在 UECM 里就能定位。

自动更新与远程版本管理

Tauri Updater 接入；多台操作机时（外景 + 公司）保持 UECM 版本同步。

SCOPE

这份路线图刻意把"自动化采集"和"分布式采集"放在 NEXT 而非 NOW —— 它们都需要真实 GPU + 真实工程做 PoC，不是改代码就能完成的。优先级由现场操作员反馈决定，不由 Roadmap 决定。
