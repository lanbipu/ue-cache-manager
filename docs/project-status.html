术语速查
下面文档里反复出现的缩略词，先扫一眼，免得读到一半要去查
DDC
Derived Data Cache。UE 把材质 / Shader 烘焙好的中间产物，省得每次重新算
PSO
Pipeline State Object。GPU 流水线状态快照，先预热好切场景不卡
WinRM
Windows 远程管理协议，UECM 跑远程脚本走它，端口 5985
CIDR
IP 段写法，如 192.168.10.0/24 表示 256 个 IP 的范围
DPAPI
Windows 自带的本机加密 API，密码绑当前用户落盘，搬到别处解不开
PsExec64
Sysinternals 工具，能用 SYSTEM 身份跑命令，用来把凭据注给系统服务
Robocopy
Windows 自带的多线程拷贝工具，断点续传友好
CVar
UE 引擎运行时配置开关，r. 开头的那些
.ddp
UECM 打包出来的 DDC 缓存文件（自定义后缀）
.uproject
UE 项目入口文件，每个项目根目录都有一个
Quick Start · 从零到稳跑
5 步把集群从零跑通。每步各对应 §02 一个验证场景。
主路径方向
  1. 1
    上线纳管
    目标机没开 WinRM 先跑 USB Bootstrap；之后网络发现 → 刷新硬件信息 → 绑定凭据。
    → 场景 A
  2. 2
    配置 & 共享
    建共享盘（推荐专用账号 Mode B），单台或整批下发环境变量和 INI 配置。
    → 场景 B
  3. 3
    健康检查 & 修复
    INI Scanner 扫出漂移项一键修；Cluster Health Check 给出 11×N 红绿矩阵。
    → 场景 C
  4. 4
    DDC 缓存分发
    源机用 UE commandlet 生成 .ddp 缓存包，Robocopy 并发推到全集群。
    → 场景 D
  5. 5
    PSO 管线
    跑一遍场景收 PSO → 推到 GPU 型号匹配的目标机 → 切场景不再卡顿。
    → 场景 E

DDC Pak
DDC 打包 · 产物工作流

把 Derived Data Cache 打成 .ddp 包，再 Robocopy 并发推到目标机。生成 + 分发是两个独立任务流，在这屏左右两栏并排跑。

屏上能看到
  • 3 块 KPI：项目 / 运行中（实际过滤 spawning|running|verifying 三态）/ 已完成
  • 左栏 生成任务：空态 暂无 DDC 打包任务 + 生成一个 DDC 包以填充此列表。；否则每个 job 一张 PakJobCard，卡片自带 cancel emit
  • 右栏 分发任务：空态 暂无分发任务运行。；否则渲染 DistributeProgressTable，每台目标机一行（当前字节 + ✓ / ✗ / ↻ 状态）
能干什么
  • 顶栏 生成 → DdcPakWizard（传 projects + locations + machines + credentials）
  • Wizard 8 步：选项目 → 确认引擎版本 → 校验 DDC → 收集产物 → 压缩成 .ddp 包 → 分发 → 客户端验证 → 归档报告
  • 每个 PakJobCard 内部都有 取消 按钮（emit cancel 到 store）

PSO Cache
PSO 缓存 · Shader 流水线

解决切场景卡顿。同屏并列两类任务：左栏看已采集文件，右栏同时跑 collect job 和 distribute job。GPU 一致性矩阵在 Health Check 屏。

屏上能看到
  • 3 块 KPI：项目 / 活跃 / 已采集
  • 左栏 已采集文件：header 带项目下拉（默认 选择项目，单项目时自动选中）；未选时空态 未选择 PSO 项目 + 选择一个项目或开始一次采集任务。；已选则渲染 PsoFileExplorer
  • 右栏 任务面板：collect job 用 PsoJobCard（传 source / project label，可取消）；distribute job 自渲染 分发 · {jobId} + status badge + targets 表，每个 target = host + 状态徽章 ok / err / running / unknown
  • 任务区空态：暂无 PSO 任务。
能干什么
  • 顶栏 采集 → PsoCollectWizard（选源机 + 项目 + 测试关卡，跑 UE runner 录 PSO）

INI Scanner
INI 扫描 · 配置漂移

跨机批量扫 project / user / engine 三类 INI 文件，哪里配置不对就列成一条「漂移项」。一键改，自动留备份。顶部有个全局应用凭据下拉，下面所有漂移项的修复动作都走这凭据。

屏上能看到
  • 4 块 KPI：严重 / 警告 / 健康 / 文件（tone: critical / warning / healthy / info）
  • 顶部全局 应用凭据 下拉：占位 选择用于应用的凭据，列出全部 credentials.alias；选完之后下面任何漂移项的修复都走这凭据
  • 空态：file-search 图标 + 标题 运行一次 INI 扫描 + hint 本次会话尚未收集到诊断结果。
  • 有漂移项时：两栏 grid，左 FindingHierarchy（按机器分组的漂移项树）、右 FindingDetail（细节面板）
能干什么
  • 顶栏 开始扫描 → IniScanWizard（选机器范围 + INI 类型）
  • 选中漂移项 → 应用建议（需先选凭据）或 跳过
  • FindingDetail 内 4 个 CTA：应用建议 / 自定义编辑 / 打开文件 / 跳过
  • apply 自动生成 .bak 备份；从 .bak 可回滚

健康检查 · 矩阵

P · 01 Onboarding
Onboard a brand-new host
目标机还没开 WinRM，用 Bootstrap 包走通第一次
  1. 主控机跑 powershell -File .\ps-scripts\package-winrm-bootstrap.ps1 -OutputDirectory E:\UECM-Bootstrap 打包
  2. 把生成目录拷到 U 盘或共享盘，搬到目标机任意路径
  3. 目标机以管理员身份运行 bootstrap-winrm-remote.ps1
  4. 主控机打开 UECM Machines 视图 → Add Machine → 填目标 IP，点 Probe
  5. 出现绿色 ONLINE 徽标，纳管完成
Prereq
目标机有管理员账号能跑 PowerShell；和主控机同网段或可路由
Expect
5985 端口监听；Machines 列表出现新行，status = online

Test-NetConnection <ip> -Port 5985

  2. UECM 并发扫 5985 / 445 端口
  3. 有回应的 IP 自动写入数据库，UI 立刻出现新行
  4. 对每台新机点 Refresh，拉回 UE 版本和 GPU 信息

  3. Machines 选目标机 → Refresh with credential alias

Expect

建专用账号共享盘，确认 LocalSystem 服务能挂上去

  1. 单台：Machine detail → Env Vars → New / Edit → Apply

  3. 到目标机确认原文件和 .bak 都存在

§ 04Roadmap after v1.0

不是排期，是方向上的押注。每条都标了投入量级。

9 ideasnot committedopen for debate
R · 01Quick Win
Headless API mode
不用开界面，外部脚本直接调

把 Tauri commands 拆出来做成本地 HTTP / gRPC 服务，CI 系统或调度器可以直接触发健康检查、批量 INI 修复、PSO 分发，不需要有人盯着 UI。

夜里没人守着，集群该跑的检查还得自己跑

R · 02Quick Win
Scheduled maintenance
定时任务自动维护

类 cron 调度：每天凌晨自动跑健康检查，每周自动重新生成 DDC 包并推到全集群，不需要人记着。

靠人记得按按钮，总有忘的时候

R · 03Explore
Telemetry export
把数据吐到 Grafana 看趋势

接 Prometheus / OpenTelemetry，把 Health Check 结果、DDC / PSO 分发耗时都做成 metric，在 Grafana 里看历史曲线。

快照只告诉你现在坏没坏，趋势才能告诉你在变好还是变坏

R · 04Moon Shot
Anomaly detection
自动发现健康状态突变

对历史 Health Check 时间序列做轻量异常检测：一台机从「长期绿」突然变「红黄交替」就推送告警，并附上可能的原因猜测。

人眼盯不住 N 台机器 11 行矩阵的长期变化

R · 05Explore
Render queue integration
任务派发前自动踢掉坏机器

和 Deadline / Tractor 对接：任务派发前自动跑一次目标机 Health Check，检测不通过的直接从可用池里摘掉，不参与本次渲染。

坏机器混进队列，整批任务都得重跑

R · 06Quick Win
Lark / Slack alerting
出红格就 @ 到运维群

Health Check 出现新红格就自动发飞书消息到运维群，附机器名 + 失败的检查项 + 建议怎么处理。用 lark-cli skill 接最快。

群里被 @ 比让人主动开 UECM 刷仪表盘，反应快多了

R · 07Moon Shot
Plugin SDK
让各项目组自己写规则挂进来

把 INI 规则引擎、Health probe、自定义 CVar 校验做成插件接口，每个项目组可以自己写专属规则，不用等主项目发版。

规则永远加不完，让用户自己加比等我们改代码快

R · 08Quick Win
Audit log for all writes
每次写操作都留记录

所有 env / INI / 共享 / 凭据写入操作全部写进本地 SQLite 审计表：谁操作、改了哪台机、改了什么、什么时间、改前改后的值。

出问题翻日志能直接知道谁动过，省去扯皮

R · 09Explore
Multi-site cluster
多片场、多地点，各管各的分发

机器按 site 分组，逻辑项目可以跨 site 共享，但 DDC / PSO 分发路径各自独立，不用跨城走公网同步。

团队大了就是多地办公，"全是一个集群"这个假设早晚撑不住
