Quick Start
五步把集群从零跑通。每步都对应 §03 一个验证场景，可在浏览器里点过去看完整步骤。

  1. 1

    上线纳管

    目标机没开 WinRM 先跑 USB Bootstrap；之后网络发现 → 刷新硬件信息 → 绑定凭据。

    → 场景 A
  2. 2

    配置 & 共享

    建 Mode B 共享盘；单台或整批机器下发 env var 和 INI 配置。

    → 场景 B
  3. 3

    体检 & 修复

    INI Scanner 扫出违规一键修；Cluster Health Check 给出 11 × N 红绿矩阵。

    → 场景 C
  4. 4

    DDC 缓存分发

    源机跑 commandlet 生成 .ddp pak，Robocopy 并发推到全集群。

    → 场景 D
  5. 5

    PSO 管线

    跑一遍场景收 PSO → 推到 GPU 型号匹配的目标机 → 切场景不再卡顿。

    → 场景 E

    Machines

    机器列表 · 清单
    F-01 发现 F-02 刷新 F-03 凭据 F-04 单机改 F-06 批量 → 场景 A

    集群里所有 Windows 机器的清单。点一行看详情，勾多台做批量操作，日常打开频率最高的一个屏。

    • 左侧机器表：hostname / IP / 状态徽标 / UE 版本 / GPU 摘要
    • 右侧详情面板：选中一台后显示完整硬件信息 + env vars + INI 文件入口
    • 多选状态条：勾几台机器后浮出来，批量操作都在这里触发
    能干什么
    • Discover：扫一段 CIDR，把能通的机器自动收进来
    • Add Machine / Refresh / Rename：手动加机器、刷新硬件信息、改 hostname
    • Batch Env Var / Batch INI：多选机器，一次下发配置
    • 给单台机器或批量绑定凭据 alias

    PSO Cache

    PSO 缓存 · Shader 流水线
    F-10 PSO P-12 全闭环 → 场景 E

    解决切换场景时的卡顿问题。先确认 CVar 开关没问题，再在源机录一次 PSO，然后推到 GPU 型号一致的目标机，最后看矩阵确认哪些机器可以用。

    屏上能看到
    • CVar 状态条：R008–R010 是否全绿（PSO 预缓存 CVar 是否已开）
    • PSO 文件清单：哪些机器收过、文件大小、来自哪次 collect
    • GPU 一致性矩阵：源机和目标机的 GPU 型号 / 驱动版本是否匹配
    能干什么
    • Collect：选源机 + 项目 + 测试关卡，跑 UE runner 录一次 PSO
    • Distribute：把 PSO 文件推到 GPU 型号一致的目标机
    • 查看 GPU Consistency Matrix，确认哪些目标机能接收

    Shares

    SMB 共享 · Shared DDC
    F-05 共享盘 P-05 Mode B

    目标机上已建的 SMB 共享清单，加上新建向导。DDC / PSO 往目标机推文件之前，目标机得先有共享盘，就在这里建。

    屏上能看到
    • 共享列表：host / 路径 / 是 Mode A 还是 Mode B / 授权账号
    • 每行带一个状态：本机当前能不能挂载
    能干什么
    • New Share · Mode A：开 Guest + Everyone:Full，适合信任内网直接用
    • New Share · Mode B：建 ddc-svc 专用账号，PsExec64 注入 SYSTEM 凭据，让系统服务也能挂载

    INI Scanner

    INI 扫描 · 配置漂移
    F-07 扫描 P-08 一键修 → 场景 C

    跨机器批量扫 project / user / engine 三类 INI 文件，哪里配置不对列出来，一键改掉还自动备份，改坏了能还原。

    屏上能看到
    • 层级结果树：机器 → INI 文件 → 触发了哪条规则
    • 三栏诊断：What 是什么问题 / Why 为什么是问题 / Symptom 不改会怎样
    • before / after diff：修复前后对比，确认没改错再提交
    能干什么
    • New Scan：选机器范围 + INI 类型，跑一次扫描
    • Apply Fix：一键改写 INI，自动生成 .bak 备份
    • Restore from backup：从 .bak 回滚到改之前的状态
  • 8 / 8 Sidebar · 8 / 8

    Health Check

    健康检查 · 矩阵
    F-08 健康 P-09 体检 → 场景 C

    全集群健康状态一张红绿矩阵看完，11 行 × N 台机器。每台机只发一次 WinRM，远端跑 8 项主动探测，另外 3 项在本地推算出来。

    屏上能看到
    • 11 × N 矩阵：每格绿 / 黄 / 红一个，一眼看出哪台机器出了问题
    • 11 项检查：smb / firewall_445 / share_reachable / ntfs_perm / cred_user / cred_system / env_vars / system_write + ini_consistency / pso_precaching / gpu_consistency
    • 探针详情：点任意格子看 Symptom + How-to-fix + 探针原始输出
    能干什么
    • Run Health Check：选机器范围，跑一次全量探测
    • 查历史 run 记录，对比哪些红格这段时间变化了

  • P·01 Onboarding Bootstrap

    Onboard a brand-new host

    目标机还没开 WinRM，用 Bootstrap 包走通第一次
    1. 主控机跑 powershell -File .\ps-scripts\package-winrm-bootstrap.ps1 -OutputDirectory E:\UECM-Bootstrap 打包
    2. 把生成目录拷到 U 盘或共享盘，搬到目标机任意路径
    3. 目标机以管理员身份运行 bootstrap-winrm-remote.ps1
    4. 主控机打开 UECM Machines 视图 → Add Machine → 填目标 IP，点 Probe
    5. 出现绿色 ONLINE 徽标，纳管完成
    Prereq目标机有管理员账号能跑 PowerShell；和主控机同网段或可路由
    Expect5985 端口监听；Machines 列表出现新行，status = online
    VerifyTest-NetConnection <ip> -Port 5985
  • P·02 Discovery Inventory

    Network discovery via CIDR scan

    给一段 IP 范围，自动把能连的机器都找出来
    1. Machines View → Discover → 填 CIDR，如 192.168.10.0/24
    2. UECM 并发扫 5985 / 445 端口
    3. 有回应的 IP 自动写入数据库，UI 立刻出现新行
    4. 对每台新机点 Refresh，拉回 UE 版本和 GPU 信息
    Prereq主控机能访问目标网段；目标机 WinRM 已开启
    Expect秒级返回所有能通的主机；不通的不写库
    Verify入库数量与 nmap -p 5985 <cidr> 结果一致
  • P·03 Inventory Refresh

    Refresh a machine's UE / GPU inventory

    更新目标机当前的 UE 版本、GPU、驱动、显存数据
    1. Machines View → 选目标机器行 → 点 Refresh
    2. UECM 经 WinRM 远程跑 query-ue-versions.ps1 + query-gpu-driver.ps1
    3. 右侧 detail panel 实时更新
    Prereq目标机装了至少一个 UE 版本；GPU 驱动安装正常
    ExpectUE 版本列表有内容；GPU 行显示型号 + 驱动版本 + VRAM
    Verifylast_seen_at 时间刷新；RTX 3080 显示 10240 MB
  • P·04 Credentials Verified

    Store and verify a credential alias

    建一条凭据别名，验证 WinRM 调用能取到
    1. Settings → Credentials → New Credential
    2. 填别名、用户名、密码 → 保存（DPAPI 加密 + cmdkey 注册）
    3. Machines 选目标机 → Refresh with credential alias
    4. 跑一次 Health Check，cred_user 行应为绿色
    Prereq目标机存在该账号并有所需权限
    Expectcreds.bin 生成；cmdkey /list 能看到对应条目
    VerifyHealth Check cred_user = OK

  • P·05 Shares Mode B

    Create a Mode B share + verify SYSTEM mount

    建专用账号共享盘，确认 LocalSystem 服务能挂上去
    1. Shares View → New Share → 选 Mode B
    2. 填本地账号名（默认 ddc-svc）、共享路径、共享名称
    3. UECM 自动在目标机建账号 → 配权限 → 开共享 → 把凭据注入 SYSTEM
    4. Health Check 跑一下，cred_system + system_write 应为绿色
    Prereq目标机管理员凭据已录入 UECM；PsExec64.exe 已下发到目标机
    ExpectLocalSystem 身份下 UNC 路径可访问，服务可写
    Verifypsexec -s -i cmd /c "dir \\<host>\<share>"
  • P·06 Config · Env Batch ready

    Edit a system env var (single + batch)

    单台或全集群同时写系统环境变量
    1. 单台：Machine detail → Env Vars → New / Edit → Apply
    2. 批量：Machines View 多选机器 → Batch → Set Env Var
    3. 实时看每台机的 ✓ / ✗ / ↻ 进度状态
    Prereq目标机 WinRM 在线；绑定的凭据有写注册表权限
    Expect目标机注册表 HKLM\SYSTEM\…\Environment 写入新键
    Verify目标机重新登录后 echo %<KEY>% 输出预期值
  • P·07 Config · INI Backup

    Edit an INI key with backup recovery

    远程改 INI 配置，验证写坏了能从备份还原
    1. Machine detail → INI Files → 选目标 INI → 定位 section/key
    2. 改值 → Apply → UECM 自动生成 .bak
    3. 到目标机确认原文件和 .bak 都存在
    4. 故意写个错值 → Restore from backup → 验证还原成功
    Prereq目标 INI 文件存在且有写入权限
    Expect值已替换；同目录有 <file>.bak；UTF-8 BOM 自动处理
    Verify还原后 diff <file> <file>.bak 输出为空

C体检 & 修复INI 违规一键修，健康矩阵一眼看清

P-08→ P-09
  • P·08 Diagnostics One-click

    Run INI Scanner + apply one-click fix

    扫全集群 INI 配置，选一条违规修掉
    1. INI Scanner View → New Scan → 选机器范围 + INI 文件范围
    2. 等扫完，结果按 R001–R010 分组列出
    3. 挑一条展开，看 What / Why / Symptom 三列
    4. 点 Apply Fix → 对照 before / after diff → Confirm
    5. 再跑一次 Scan，确认这条不再出现
    Prereq目标机已加入 UECM；INI 文件存在于目标路径
    Expect违规列表刷新；diff 视图显示正确；.bak 已写到目标机
    Verify第二次 Scan 该条不再出现

    Run cluster Health Check

    跑一次，全集群 11 行 × N 列结果一次出
    1. Health Check View → 选机器范围 → Run
    2. 每台机器只发一次 WinRM 请求，打包跑 8 项主动探测
    3. 另 3 项在主控本地计算完成
    4. 点任一红格 → 右侧看 Symptom + How-to-fix + 探针原始输出
    Prereq目标机 WinRM 在线；最好先跑过一次 INI Scan
    Expect11 行全部有结果，没有 Pending 停在那
    Verifylist_recent_health_runs 返回新记录；得分 = 通过数 / 总项 × 100

DDDC 缓存分发从源机打包 DDC 缓存，推到整个集群

P-10→ P-11
  • P·10 DDC · Generate UE runner

    Discover projects + generate DDC pak

    自动扫项目，让 UE 跑 commandlet 生成 .ddp 包
    1. Projects View → Discover Projects → 选源机 → WinRM 扫 .uproject 文件
    2. UECM 自动按项目身份匹配为「逻辑项目」
    3. DDC Pak View → New Generation → 选项目 + 源机 + 目标 .ddp 输出路径
    4. 后台拉起 UE commandlet，实时推 stdout / stderr 到 UI
    5. 结束后检查 pak 文件大小和 sha256
    Prereq源机装了项目对应的 UE 版本；DDC 缓存至少预热过一次
    Expect.ddp 文件已生成；UECM 记录文件大小 + checksum
    Verifyverify-pak-output.ps1 退出码 = 0
  • P·11 DDC · Distribute Robocopy

    Distribute DDC pak to N hosts

    Robocopy 并发把 .ddp 推到多台目标机
    1. DDC Pak View → 选已生成的 pak → Distribute
    2. 多选目标机器（需映射到同一逻辑项目）→ Confirm
    3. 每台机器并发跑 Robocopy，独立上报进度
    4. 某台失败不影响其余 N-1 台继续跑
    Prereq目标机上 DDC 共享盘已建好（见 P-05）
    Expect每台机器有 ✓ 或 ✗ 终态，附已传字节数
    Verify目标 UNC 路径出现 .ddp，大小与源文件一致

EPSO 缓存管线跑场景收 PSO，推到 GPU 型号匹配的机器

P-12
  • P·12 PSO · Full loop GPU gate

    Collect PSO + distribute + verify GPU consistency

    PSO 四步闭环从头到尾走一遍
    1. 先跑 INI Scanner，确认 R008–R010 全绿（PSO CVar 已开）
    2. PSO Cache View → Collect → 选源机 + 项目 + 测试关卡
    3. UE runner 跑一遍场景，UECM 自动抓取生成的 PSO 文件
    4. Distribute → 选 GPU 型号相同的目标机集合
    5. 看 GPU Consistency Matrix（F4），确认目标机 GPU 和源机匹配
    Prereq源机装了实体 GPU 并接了显示器；项目里至少有一个能渲染的 map
    ExpectPSO 文件落到源机；目标机收到副本；GPU matrix 同型号同驱动全绿
    Verify切场景不再卡顿；Health Check pso_precaching = OK
§ 04 · OPEN FOR DEBATE

Roadmap
after v1.0不是排期，是方向上的押注。每条都标了投入量级：Quick Win（一两天能落）、Explore（要先做 PoC）、Moon Shot（值得做但难）。

9 ideas not committed
open for debate
Sorted by impact / effort
  1. R·01Quick Win

    Headless API mode

    不用开界面，外部脚本直接调

    把 Tauri commands 拆出来做成本地 HTTP / gRPC 服务，CI 系统或调度器可以直接触发健康检查、批量 INI 修复、PSO 分发，不需要有人盯着 UI。

    夜里没人守着，集群该跑的检查还得自己跑。— Pain point
  2. R·02Quick Win

    Scheduled maintenance

    定时任务自动维护

    类 cron 调度：每天凌晨自动跑 Health Check，每周自动重新生成 DDC pak 并推到全集群，不需要人记着。

    靠人记得按按钮，总有忘的时候。— Pain point
  3. R·03Explore

    Telemetry export

    把数据吐到 Grafana 看趋势

    接 Prometheus / OpenTelemetry，把 Health Check 结果、DDC / PSO 分发耗时都做成 metric，在 Grafana 里看历史曲线。

    快照只告诉你现在坏没坏，趋势才能告诉你在变好还是变坏。— Pain point
  4. R·04Moon Shot

    Anomaly detection

    自动发现健康状态突变

    对历史 Health Check 时间序列做轻量异常检测：一台机从「长期绿」突然变「红黄交替」就推送告警，并附上可能的原因猜测。

    人眼盯不住 N 台机器 11 行矩阵的长期变化。— Pain point
  5. R·05Explore

    Render queue integration

    任务派发前自动踢掉坏机器

    和 Deadline / Tractor 对接：任务派发前自动跑一次目标机 Health Check，检测不通过的直接从可用池里摘掉，不参与本次渲染。

    坏机器混进队列，整批任务都得重跑。— Pain point
  6. R·06Quick Win

    Lark / Slack alerting

    出红格就 @ 到运维群

    Health Check 出现新红格就自动发飞书消息到运维群，附机器名 + 失败的检查项 + 建议怎么处理。用 lark-cli skill 接最快。

    群里被 @ 比让人主动开 UECM 刷仪表盘，反应快多了。— Pain point
  7. R·07Moon Shot

    Plugin SDK

    让各项目组自己写规则挂进来

    把 INI 规则引擎、Health probe、自定义 CVar 校验做成插件接口，每个项目组可以自己写专属规则，不用等主项目发版。

    规则永远加不完，让用户自己加比等我们改代码快。— Pain point
  8. R·08Quick Win

    Audit log for all writes

    每次写操作都留记录

    所有 env / INI / 共享 / 凭据写入操作全部写进本地 SQLite 审计表：谁操作、改了哪台机、改了什么、什么时间、改前改后的值。

    出问题翻日志能直接知道谁动过，省去扯皮。— Pain point
  9. R·09Explore

    Multi-site cluster

    多片场、多地点，各管各的分发

    机器按 site 分组，逻辑项目可以跨 site 共享，但 DDC / PSO 分发路径各自独立，不用跨城走公网同步。

    团队大了就是多地办公，「全是一个集群」这个假设早晚撑不住。— Pain point
