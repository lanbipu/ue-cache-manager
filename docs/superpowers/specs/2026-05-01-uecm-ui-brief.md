## 1. 产品全景

### Goal（目标）

UECM 是一款 Windows 桌面工具，让用户能在一台电脑上集中管理整个局域网内 4-30 台机器（包括渲染节点、开发机、共享存储 Host）的 Unreal Engine 项目缓存配置。覆盖两大缓存类型：DDC（Derived Data Cache，编译产物）和 PSO Cache（GPU 管线状态）。最终目标：让任何一台新机器打开 UE 工程都能"零编译启动 + 零卡顿运行"。

### Audience（用户）

VP/XR（虚拟拍摄 / 扩展现实）现场技术总监（TD）、运维工程师。技术背景强，平时使用 VS Code、Wireshark、Visual Studio、各种命令行工具。**追求信息密度和操作效率**，而非"消费级 App 美感"。能接受密集表格、专业术语、多步操作流程。

### Content（核心内容类型）

- 机器清单（IP、状态、UE 版本、GPU、健康度等）
- 项目清单（UE 项目、跨机路径映射）
- 配置数据（环境变量、ini 文件内容、共享盘 UNC 路径）
- 操作记录（历史、进行中任务）
- 诊断结果（INI 冲突、健康检查、PSO 一致性）

### Context（使用情境）

- 工具运行在一台"操作机"上，连接局域网内其他机器
- 用户经常在三种模式间切换：
  - **观察模式**：看集群整体状态、找异常
  - **操作模式**：选目标 → 配参数 → 预览 → 执行 → 看进度
  - **诊断模式**：发现问题 → 看根因 → 修复
- 单次工作时长 5 分钟到几小时不等
- 部分操作（如 PSO 采集）耗时极长（小时级），用户可能切走做别的事

## 2. 信息架构

### 一级视图清单（共 7 个）

用户需要在以下 7 个视图间切换：

| # | 视图 | 主要解决的问题 |
|---|---|---|
| 1 | **Dashboard** | 一眼掌握集群整体状态，决定接下来做什么 |
| 2 | **Machines** | 管理所有机器、看每台的详情 |
| 3 | **Projects** | 跨机器统一看所有 UE 项目 |
| 4 | **DDC Pak** | 生成 + 分发 DDC 缓存包文件 |
| 5 | **PSO Cache** | 采集 + 分发 PSO 缓存文件 + GPU 一致性 |
| 6 | **INI Scanner** | 扫描所有 ini 配置冲突、提供修复 |
| 7 | **Health Check** | 集群整体健康度的可视化矩阵 |

### 持久全局元素（不属于任何单一视图，全程可见）

- **机器选择入口**：用户可能在任何视图下需要快速跳到"某台机器"
- **当前任务指示器**：长时任务（如 PSO 采集）运行时，用户切到其他视图也要能看到进度
- **实时日志区**：用户经常边操作边看反馈，需要能可常驻、也可收起
- **全局通知**：操作完成、新发现告警等需要能弹出通知

### 模态层（不占主视图空间）

以下流程通过模态对话框 / 浮层呈现：
- **多步向导**：创建共享 DDC、推配置、生成 DDC Pak、采集 PSO、统一驱动等
- **凭据输入**：连接新机器需要 admin 密码
- **确认对话框**：执行不可逆操作前
- **详情查看**：单条 INI finding 的完整建议、单次操作的完整日志

## 3. 每个视图的详细 Brief

### 3.1 Dashboard

**Goal**：用户开机后第一眼掌握集群当前状态，并决定接下来做什么。

**Audience focus**：观察 + 快速跳转。

**Content（必须呈现的信息）**：
- 整体集群健康度（一个突出的百分比数字）
- 在线机器数 vs 总机器数
- 当前活跃任务数量
- 当前未解决的高危问题数量、警告数量
- 最近 5 条操作记录（含时间、动作类型、结果）
- 最近一次健康检查的时间

**Actions（用户可操作）**：
- 跳转到任意一级视图
- 启动常用向导（"创建共享 DDC"、"推配置到所有机器"等）
- 触发"立即重新检查"
- 点击告警数字直接跳到 Health Check 看详情

**Key Relationships**：
- 健康度数字 ↔ Health Check 视图（点击跳转）
- 告警计数 ↔ INI Scanner / Health Check 详情
- 最近操作记录 ↔ 该操作的完整日志详情

**States**：
- 首次启动（无机器）：引导用户去扫描局域网
- 检查进行中：相关数字应有 loading 状态
- 有未读高危告警：应有视觉强调
- 有任务运行中：进度可感知

---

### 3.2 Machines

**Goal**：管理所有局域网机器的清单，查看每台的详细信息和配置。

**Audience focus**：观察 + 单机操作 + 多机对照。

**Content**：

机器清单中每个机器项需要呈现：
- 在线/离线状态
- 机器名 + IP 地址
- 角色标签（Host / Render Node / Dev / Editor）
- 已装的 UE 版本（可能多个）
- 健康状态摘要（绿/黄/红）

机器详情中需要呈现：
- 基础：机器名、IP、操作系统、最后在线时间
- 硬件：CPU 摘要、内存、**GPU 型号、GPU 驱动版本**
- 已装 UE 版本清单及各自的安装路径
- 当前 DDC 配置：环境变量值、相关 ini 配置摘要
- 共享盘连接状态：连了哪个 UNC、凭据状态
- 该机器在 11 项健康检查中的状态（绿/黄/红）
- 该机器上所有 UE 项目的清单及路径

**Actions**：
- 在清单中选择一台机器查看其详情
- 同时打开多台机器的详情进行对照
- 添加新机器（手动输入 IP / 重新扫描局域网）
- 移除机器（不再管理）
- 单机推送配置
- 重新扫描该机器
- 在清单中按角色 / 健康状态 / UE 版本 / 在线状态筛选
- 在清单中按多个字段排序
- 在清单中按机器名搜索

**Key Relationships**：
- 选中清单中的机器 → 显示该机器的详情
- 详情中的"该机器项目清单" → 跳转到 Projects 视图查看该项目
- 详情中的"健康状态" → 跳转到 Health Check 看完整矩阵

**States**：
- 机器离线：在清单中视觉标识，详情面板显示"离线"提示
- 正在扫描局域网：进度可感知
- 新发现机器：需要视觉强调（让用户注意到）
- 没有任何机器（首次使用）：空状态引导

---

### 3.3 Projects

**Goal**：跨机器统一看所有 UE 项目，及它们在每台机器上的位置。

**Audience focus**：观察项目分布 + 配置跨机映射。

**Content**：

项目清单中每个项目项需要呈现：
- 项目名（来自 .uproject 文件名）
- 关联的 UE 版本
- 在多少台机器上发现（数量徽章）
- INI 状态摘要（健康/有警告/有冲突）
- 最近一次相关操作时间

项目详情需要呈现：
- 元信息：名称、UE 版本、内部 GUID
- **机器位置映射表**：每行一台机器，显示该项目在该机器上的具体路径，**支持手动编辑映射**（这是关键功能：跨机器项目身份匹配，详见章节 4.7）
- 该项目最新 DDC Pak 的状态（有/无、生成时间、已分发到哪些机器）
- 该项目最新 PSO Cache 的状态
- 该项目所有 ini 文件的健康状态摘要

**Actions**：
- 在清单中选择项目查看详情
- 手动编辑"项目在 A 机器路径 = B 机器哪个路径"的映射
- 删除一个项目记录（不再追踪，并不删除实际文件）
- 启动针对该项目的操作（生成 DDC Pak / 采集 PSO / 扫描 INI / 推配置）

**Key Relationships**：
- 项目详情中的"在某台机器" → 跳转到 Machines 视图看该机器
- 项目的"DDC Pak 状态" → 跳转到 DDC Pak 视图看历史任务
- 项目的"INI 状态" → 跳转到 INI Scanner 看该项目的所有 finding

**States**：
- 项目仅存在于一台机器：可能是新项目，需提示"建立映射"
- 项目映射不完整：视觉提示
- 项目在所有机器路径已映射：清晰标识"已就绪"

---

### 3.4 DDC Pak

**Goal**：DDC Pak 文件的生成与分发管理。

**Audience focus**：操作（启动任务）+ 监控（看进度）。

**Content**：

视图主要内容：
- 操作入口区：三个常用动作（"新建生成"、"新建分发"、"一站式向导"）
- 当前进行中的任务（每个任务卡片需独立可见）
- 历史任务记录列表

进行中任务卡片需呈现：
- 任务类型（生成 / 分发 / 一站式）
- 关联项目
- 源机器、目标机器（如有）
- 进度（百分比或阶段描述）
- 已用时间 + 预计剩余时间

历史任务列表需呈现：
- 时间、类型、项目、源机器、目标机器、最终状态、耗时

**Actions**：
- 启动新任务（通过向导）
- 暂停 / 取消进行中的任务
- 查看任务的完整日志
- 重做历史任务

**一站式向导的多步流程**（每步都需要：上一步 / 下一步 / 取消 / 当前步骤指示）：
1. 选模式：本机生成 / 远程生成 / 本机生成+分发 / 远程生成+分发
2. 选源机器（如非本机）
3. 选项目（列出该机器上所有 .uproject）
4. 配置生成参数（窗口分辨率，可选要遍历的关卡）
5. 选目标机器（如需分发）
6. 确认目标项目路径映射（自动 + 可手动调整）
7. **预览页**：显示要执行的 UE 命令行 + 分发计划（参见章节 4.3"预览即契约"）
8. 执行 + 实时进度

**Key Relationships**：
- 任务关联项目 → 项目详情
- 任务关联机器 → 机器详情
- 任务历史可重做 → 复用之前参数发起新任务

---

### 3.5 PSO Cache

**Goal**：PSO Cache 文件的生成、分发，以及 GPU/驱动一致性检查。

**Audience focus**：操作 + 监控 + **集群一致性可视化**（PSO 强绑定 GPU + 驱动）。

**Content**：

视图主要内容：
- **GPU/驱动一致性矩阵**：核心可视化（PSO 的关键约束）
- 操作入口区：采集 / 分发 / PSO Precaching 验证
- 当前任务 + 历史任务（结构同 DDC Pak）

GPU/驱动一致性矩阵需呈现：
- 每台机器一行，包含：机器名、GPU 型号、驱动版本、驱动日期
- 用视觉方式标注"哪些机器是同一个 GPU + 驱动组合"（让用户瞬间识别"哪几台机器可以共享同一份 PSO Cache"）
- 不一致时给出明确警告，并指出具体差异
- 提供建议（如"将 4 台机器的驱动统一升级到 545.92"）

**Actions**：

采集流程（向导）：
1. 选源机器（GPU 必须代表集群典型配置）
2. 选项目
3. 配置 UE 启动参数（分辨率、是否窗口模式、要遍历的关卡列表）
4. **警告说明**：采集需要在源机器上手动遍历场景，预计耗时 X 分钟
5. 预览（要执行的 UE 命令行）
6. 启动采集 + 实时监控（显示 UE 是否还活着、采集到的 PSO 数量）
7. 用户操作 UE 完成场景遍历后，工具检测到 UE 退出，从 `Saved/CollectedPSOs/` 收集产物
8. 显示采集结果摘要

分发流程：
- 选源 PSO Cache 文件
- 选目标机器（**必须 GPU/驱动一致**，否则警告但允许强制）
- 进度条 + 完整性校验

PSO Precaching 验证：
- 列出每台机器的相关 CVar 状态（`r.PSOPrecaching` 等）
- 未启用的标识异常
- 一键设置按钮（写入项目 ini 或设环境变量）

**Key Relationships**：
- GPU 矩阵中的机器行 → 跳转该机器详情
- 不一致警告 → 关联到"建议升级驱动"的具体操作
- PSO Cache 文件 → 关联到生成它的项目

**States**：
- 集群 GPU 完全一致：明确标识"可以共用 PSO"
- 部分不一致：分组显示，提示"这些组之间不能共用"
- 全部不一致：突出警告
- 采集进行中：源机器上 UE 是否仍活着的状态可感知

### 3.6 INI Scanner

**Goal**：扫描所有机器所有项目的 ini 配置，找出冲突，给出诊断和修复。

**Audience focus**：诊断 + 修复（这是工具的差异化救命功能）。

**Content**：

视图主要内容：
- 扫描结果摘要（健康度 + 各级别计数：高危/警告/健康）
- 筛选与分组控制
- 扫描结果详情区

扫描结果需要呈现的层级：
- 按"机器→项目→ini 文件→具体 finding"分层组织
- 也可切换为"项目→机器→ini 文件→finding"分组
- 每个层级需显示子项中的严重程度摘要（如"RENDER-02 (2 高危)"）
- 严重项需有视觉强调

单条 finding 的完整详情需呈现：
- 严重等级标签（高危 / 警告 / 健康）
- 完整文件路径
- **诊断说明**：用人话讲清"问题是什么、影响是什么、表现是什么"
- **检测到的内容**：高亮问题行的代码片段
- **建议修复**：同步显示修改后的代码片段（让用户看修改前后对比）

**Actions**：
- 重新扫描全部 / 重新扫描指定机器或项目
- 按严重程度筛选（仅高危 / 含警告 / 全部）
- 按问题类型筛选
- 按机器或项目筛选
- 切换分组方式
- 选中 finding 查看详情
- 单条 finding 操作：跳过 / 自定义改 / 打开文件手改 / 应用建议修复
- 一键修复全部（含确认对话框 + 自动备份选项）
- 导出扫描报告（HTML / Markdown / PDF）

**Key Relationships**：
- finding 关联机器 → 跳转该机器详情
- finding 关联项目 → 跳转该项目详情
- 一键修复后 → 自动触发该机器的健康检查重跑

**States**：
- 从未扫描过：空状态引导用户启动首次扫描
- 扫描进行中：进度可感知
- 全部健康：庆祝性提示
- 有未修复高危：突出强调
- 已修复但未重新扫描：提示"建议重新扫描验证"

### 3.7 Health Check

**Goal**：集群整体健康度的可视化矩阵，11 项检查 × N 台机器。

**Audience focus**：观察 + 诊断 + 直接修复。

**Content**：

视图主要内容：
- 顶部摘要：集群健康度百分比、各级别计数、上次扫描时间
- **核心可视化：矩阵**（行 = 11 项检查，列 = 机器，单元格 = 状态）
- 选中单元格的详情面板

矩阵中每个单元格的状态：
- 正常 / 警告 / 严重 / 不适用 / 离线 / 未知（共 6 种状态）

11 项检查清单（必须全部呈现）：
1. SMB 服务运行中
2. 防火墙 445 入站允许
3. 共享盘可达
4. NTFS 权限（仅 Host 适用）
5. 用户级凭据
6. **SYSTEM 级凭据 ★**（最易缺、影响 Service）
7. 环境变量正确
8. INI 配置一致性
9. **SYSTEM 写测试 ★**（终极验证）
10. PSO Precaching CVar 状态
11. GPU/驱动一致性

单元格详情面板需呈现：
- 严重等级
- 关联机器 + 检查项
- **诊断说明**（人话）
- **关联失败项**：其他相关的检查也失败时一并指出（例如检查 9 失败往往关联检查 6 失败 → 根因分析）
- **建议修复**

**Actions**：
- 立即重新检查全部 / 单台 / 单项
- 按机器排序（按失败数）
- 折叠全部正常的检查项（聚焦异常）
- 单元格点击 → 显示详情
- 一键修复（针对单个失败项）
- 导出报告
- 配置定时检查（频率、是否触发系统通知）

**Key Relationships**：
- 单元格 → 关联机器详情
- 失败项 → 关联其他相关失败项（根因关联）
- 修复后 → 自动重跑该项验证

**States**：
- 全部健康：庆祝性提示
- 有严重项：突出警告
- 检查进行中：进度可感知
- 个别机器离线：该列整体显示"离线"

## 4. 通用 UI 模式（跨视图复用，需统一表达）

### 4.1 状态指示

工具广泛使用**状态颜色编码**，以下 6 种状态需要在全工具统一表达：

| 状态 | 含义 |
|---|---|
| 正常 / 健康 | 一切 OK |
| 警告 | 可继续使用但建议关注 |
| 严重 | 阻断或重大问题 |
| 不适用 | 该检查不适用于这台机器 |
| 离线 | 机器无法连通 |
| 进行中 | 操作正在执行 |
| 未知 | 未扫描过 / 数据过期 |

设计师为这 7 种状态设计统一的视觉表达（颜色 + 图标 + 是否动态），全工具复用。

### 4.2 长任务进度

工具有大量"长任务"（推配置、生成 DDC Pak、采集 PSO、健康检查），都需要呈现：

- **整体进度**：N 台机器中 M 台完成
- **每子项独立进度**：每台机器独立的进度信息 + 当前阶段描述
- **已用时间 + 预计剩余时间**
- **失败项不阻断成功项**：单台失败立即标识，其他继续
- 提供 **暂停 / 取消 / 重试失败项** 的能力
- 完整日志可展开查看

### 4.3 "预览即契约"原则

任何写入操作（推配置、改 ini、创建共享、注入凭据等）执行前**必须**先呈现预览：

- 明确显示"将在哪台机器执行什么命令"
- PowerShell 命令明文展示，不藏黑盒
- 提供 **Dry Run 选项**：不真改，仅模拟
- 提供 **自动备份选项**：默认勾选
- 区分"可逆"和"不可逆"操作（不可逆需二次确认）

设计师为预览页设计统一的呈现模板，全工具复用。

### 4.4 错误信息

所有错误必须**结构化**展示，包含 4 个要素：

1. **是什么**（错误标题 + 严重等级）
2. **为什么**（根因诊断，用人话写）
3. **影响**（这个错误导致什么实际后果）
4. **怎么办**（建议修复 + 一键修复按钮，如可能）

不允许将原始 SDK 堆栈直接展示给用户。

### 4.5 列表 / 表格

多个视图需要**密集表格**展示数据。表格的功能性需求：

- 列可排序
- 列可筛选
- 列宽可调整
- 行选中后联动详情面板
- 大数据下需虚拟滚动（机器列表可能 30 行、INI findings 可能数百行）

### 4.6 输入控件类型

工具会用到以下输入控件：

- 文本输入（机器 IP、UNC 路径、UE 项目路径）
- 文件路径选择（含本机文件浏览 + 远程路径浏览）
- 下拉选择（UE 版本、模式选择）
- 多选（目标机器列表 —— 经常需要全选/反选/按筛选条件选）
- 数值输入（端口号、超时、并发数）
- 复选框（开关类、自动备份等）

设计师需考虑：
- 表单验证如何呈现错误
- 必填项如何标识
- 高级选项是否折叠

### 4.7 跨机器项目身份匹配（关键交互）

UECM 中"项目"是逻辑概念，可能在不同机器上有不同物理路径。例如项目 EXLY 在 Render01 上是 `D:\Work\EXLY`，在 Render02 上是 `E:\Projects\EXLY`。

**功能要求**：
- 自动匹配（按 .uproject 文件名）
- 半自动匹配（UI 列出所有发现的 .uproject，让用户点选关联）
- 完全手动（用户填路径映射表）
- 映射结果保存复用，下次分发该项目自动使用

**UI 体现**：
- Projects 视图的"机器位置映射表"是主入口
- DDC Pak / PSO 分发向导中也需要确认 / 调整映射的步骤

### 4.8 模态向导

多步骤流程统一通过模态向导呈现：

- **步骤指示**：横向显示当前步骤、已完成、待办
- **每步内容独立**：当前步骤的内容
- **导航控制**：上一步 / 下一步 / 取消，部分步骤可有"Dry Run"
- **退出确认**：用户中途想关闭时弹"已填写内容会丢失"

## 5. 典型用户流（跨视图）

### 流 1：首次部署
1. 启动工具（Dashboard 显示"无机器"）
2. 跳到 Machines → 扫描局域网 → 选 Host
3. 启动"创建共享 DDC"向导
4. 完成后回 Dashboard 看健康度

### 流 2：日常巡检
1. 看 Dashboard 发现红色告警
2. 跳到 Health Check 矩阵看具体哪台、哪项失败
3. 点击失败单元格 → 详情面板 → 一键修复

### 流 3：项目部署
1. 一个新项目从 git 拉到主机器
2. 跳到 Projects 看到新项目
3. 启动"扫描该项目 INI"检查健康
4. 启动"生成 DDC Pak" → 选目标机器分发
5. 启动"采集 PSO" → 选源 + 分发

### 流 4：排查"DDC 没生效"问题
1. 用户报告某机器 DDC 没生效
2. 跳到 Machines → 选该机器 → 看详情
3. 看健康检查结果，找异常项
4. 跳到 INI Scanner → 看该机器是否有 ini 覆盖
5. 修复 → 验证 → 完成

### 流 5：升级 GPU 驱动后
1. PSO Cache 视图发现 GPU 矩阵中某机器驱动版本不一致
2. 跳到该机器详情确认硬件信息
3. 决定是否触发新一轮 PSO 采集（向导）
4. 分发新 PSO 到一致驱动的机器组

## 6. 显式留给设计师发挥的事项

以下事项**完全交给设计师决定**，本 Brief 不做任何约束：

- **配色方案**（色板、亮色/暗色主题、各状态的具体颜色）
- **字体选择**（中英文字族、字重、字号层级）
- **间距系统**（padding、margin、grid）
- **整体设计语言**（现代 / 复古、简约 / 华丽、商务 / 极客）
- **空间布局**（左右 / 上下 / 嵌套 / 浮动 / 多面板的具体排列方式）
- **圆角、阴影、动效、过渡**
- **图标集**（用什么图标库、自绘还是开源）
- **空状态插画**
- **品牌元素**（logo、产品色）
- **微交互**（hover 状态、按钮按下反馈）
- **响应式策略**（最小窗口尺寸、缩放行为）
- **大小写规范**（Title Case vs sentence case）
- **信息密度**（紧凑 / 舒适 / 宽松）
- **导航形态**（侧栏 / 顶栏 / 活动栏 / 标签 / 浮动 / 命令面板）

设计师可以创造任何视觉方向、空间布局、组件形态——只需保证下面的"功能性硬要求"和"信息架构 + 内容映射"完全还原。

## 7. 功能性硬要求（无论什么风格都必须满足）

- **键盘可达**：常用操作支持快捷键
- **大数据表格**：需虚拟滚动
- **复制粘贴友好**：路径、命令、错误信息、机器 IP 都需要可一键复制
- **不阻塞主线程**：长任务必须异步，UI 任何时候应可响应
- **离线可用**：工具本身不依赖外网
- **状态持久化**：用户切换视图、关闭重开后，过滤器、列宽、详情面板状态等应保留
- **可访问性**：基本的颜色对比度、键盘导航、screen reader 兼容（避免仅靠颜色传达信息，需配合图标 / 文字）
