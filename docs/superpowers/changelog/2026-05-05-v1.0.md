# UECM v1.0 — Release Notes (2026-05-05)

This release closes the v1 design intent: any Render Node in a VP/XR cluster can open a UE project with zero shader recompile via DDC and reduced scene-switch hitching via PSO Cache.

## Plans Landed

- Plan 1: Tauri foundation, SQLite baseline, and navigable app shell.
- Plan 2: Network discovery, machine inventory, UE install detection, GPU detection, env var editing, and INI editing.
- Plan 3: Credential aliases, SMB share modes, SYSTEM credential injection, and cluster batch operations.
- Plan 4: INI scanner, persisted findings, one-click apply, and 11-check Health Check matrix.
- Plan 5: Project identity, DDC Pak generation, UE runner cancellation, verification, and Robocopy distribution.
- Plan 6: PSO CVar verification, PSO collection, PSO distribution, GPU consistency matrix, and visual polish baseline.

## Subsystems

- Machine inventory: CIDR scan, WinRM/SMB probing, refresh, UE installs, GPU model/driver/VRAM, hostname rename.
- Credentials and shares: DPAPI-backed aliases, cmdkey SMB auth, open and managed SMB share creation, PsExec-backed SYSTEM validation.
- Cluster operations: batch env var and INI writes with per-machine progress events.
- Diagnostics: INI rules R001-R010, scanner persistence, open finding workflow, apply/skip, Health Check matrix, and GPU matrix detail.
- Project identity: discovery of `*.uproject`, logical project grouping, manual alias/path mapping, and per-machine locations.
- DDC Pak: UE `-run=DerivedDataCache` generation, output verification, cancellation, and fan-out distribution.
- PSO Cache: UE `-game` collection with watchdog, collected file persistence, GPU signature capture, mismatch-guarded distribution, and frontend file explorer.
- Frontend: Pinia stores for DDC/PSO/GPU/health, reusable primitives, Dashboard KPIs, shared state block, and modal workflows.

## Known Limitations

- WinRM, registry, Credential Manager, Robocopy, and UE automation paths are Windows-only.
- macOS/Linux are supported for local development and non-Windows-gated tests only.
- lanPC E2E was not completed in this pass because `192.168.10.20` was unreachable (`ping`: 2 transmitted / 0 received; `ssh lanpc`: port 22 timeout).
- PSO collection still requires manual viewport driving; no automated camera flythrough is included.
- Robocopy is the only transport; no chunked or resumable transfer mode.
- AMD / Intel GPUs are unvalidated in E2E; NVIDIA is the target validation path.
- Single-operator workflow only; no RBAC or multi-user audit layer.
