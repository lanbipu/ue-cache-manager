## What shipped

Four new CLI domains for AI / human callers to drive UECM's DDC configuration
workflow without the WebView, plus two shared argument helpers reused across
domains.

### Shared argument helpers

- `cli::credential_args::CredentialArgs` — `--cred-alias` / `--user --pass` /
  `--user --pass-stdin` with full clap mutex (`group="cred"`, `group="secret"`,
  `conflicts_with_all`). `resolve(&db)` returns `Option<(String, String)>`.
- `cli::host_args::HostArgs` — `--host` / `--hosts a,b,c` mutex via
  `group="target"`. `require_one()` returns `HostTarget::Single|Batch`.

### `cred` domain

- `cred list` — `data::credentials::list_all`
- `cred save` — 5-step transactional sequence mirroring `commands/credentials.rs::save_credential`:
  validate `--kind` (winrm / share, reject typos) → normalize username →
  cmdkey store → DPAPI store (rollback cmdkey on fail) → SQLite replace-or-insert
- `cred delete` — 4-step best-effort cleanup mirroring UI:
  cmdkey delete (preserve result) → SQLite hard delete → DPAPI best-effort → return cmdkey result

### `env` domain

- `env get --host <h>` — single host; the only command authorized to surface raw value
- `env set --host <h>` / `env set --hosts a,b,c` — single + batch with NDJSON
  event stream (`started` → `item_started`/`item_completed` × N → `completed`)

### `ini` domain

- `ini read --host <h>` — single host, surfaces section keys
- `ini set --host` / `ini set --hosts` — single + batch with redaction
- `ini remove --host` / `ini remove --hosts` — single + batch (requires creds)

### `share` domain

- `share list` — `data::share_configs::list_all`
- `share forget <id> --yes` — LOCAL inventory delete only. Spec-renamed from
  `share delete` to make the local-only semantics explicit. Remote SMB +
  `Remove-LocalUser` + cmdkey cleanup parked under `share remove` (future)
- `share create --mode a|b` — Mode A open Guest+Everyone; Mode B provisions
  `ddc-svc` with random 24-byte base64url password, persisted to DPAPI under
  alias `share-<host>-<share>` for later `inject-system-cred` lookup
- `share inject-system-cred --client-host --target-host` — resolves svc
  password via DPAPI alias prefix `share-<target_host>-`, calls
  `core::psexec::inject_system_credential`

### Cross-cutting

- **Redaction contract (spec §8)** — `env set` / `ini set` never echo raw
  `value` in stdout / stderr / NDJSON. Only `value_len` + `value_sha256_prefix`
  (sha2 first 4 bytes hex) surface in metadata. Error messages get a
  substring `replace(value, "[REDACTED:value]")` pass at handler level.
- **clap exit code preservation** — all credential / host arg mutex violations
  fail at clap parse time with exit 2 (invalid_input).
- **DB-free integrity** — every new domain is `needs_db: true`; existing
  `needs_db` rule for `system version` / `system ps-dir` / `machine scan` /
  `winrm bootstrap-script` preserved.

## Codex adversarial review

The spec went through one adversarial review before plan-writing (3 findings,
all addressed in spec §5.1.1 / §5.4 / §8). During implementation, every task
triggered a post-commit Codex review. Across the run Codex flagged 9 issues —
8 fixed in the same task that introduced them (or its follow-up commit), 1
confirmed false positive (`Box<dyn Emitter>` 'static lifetime in tests; Rust
trait-object lifetime elision picks the surrounding borrow lifetime here, 211
lib tests + 6 integration tests all compile and run green).

Notable fixes:

- `cred save --kind <typo>` was silently falling back to `Winrm` after
  cmdkey + DPAPI had already succeeded; now validates `--kind` before any
  side effect and returns `invalid_input`.
- `machine refresh` (Plan 1 retrospective) was marking the oldest UE install
  as primary because PowerShell sorts versions ascending; now picks the
  highest version using numeric `(major, minor)` compare so future UE 5.10
  doesn't lose to UE 5.8 in lexicographic order.
- `machine delete` (Plan 1 retrospective) used to report success for
  nonexistent ids; now `find_by_id` first and returns `invalid_input`.
- `winrm bootstrap` (Plan 1 retrospective) accepts `--pass-stdin` so the
  remote admin password no longer needs to enter argv / shell history.
- Plan-2 `CredentialArgs` initially let `--cred-alias x --pass p` slip past
  clap; pass and pass-stdin now `conflicts_with_all = [..., "cred_alias"]`.
- Redaction guard had `if value.len() >= 4` — short secrets `abc` / `p1` could
  leak via setx-machine.ps1's verification echo; now `if !value.is_empty()`.

## lanPC end-to-end (deferred)

Capability ② end-to-end on lanPC (cred save → list → env set → env get →
ini read → share create → share list) **not yet executed** — `192.168.10.20`
was unreachable at the time of Plan 2 shipping (`ssh: connect to host
192.168.10.20 port 22: Operation timed out`). The CLI itself is
production-ready (lib + integration tests + redaction grep all green); the
end-to-end script lives in the plan §6.2 and can be replayed whenever lanPC
comes back online. Deferring this step does not block Plan 3 (which will
build on Plan 2's domain handlers but does not require lanPC validation of
Plan 2 first).

## Out of scope (deferred to Plan 3+)

- **`ini` cluster scan** (`scan` / `findings` / `apply` / `skip` / `runs` /
  `get-finding`) — Plan 3 (capability ③ "cluster DDC config discovery")
- **`machine refresh` with `--cred-alias` flag** — Plan 1 deferred entry;
  Plan 3 will add `core::winrm::probe_with_credential` +
  `core::discovery::detect_*_with_credential` and wire them
- **`share remove`** — the destructive variant with `Remove-SmbShare` +
  `Remove-LocalUser ddc-svc` + cmdkey clear; needs a new ps-script
- `ddc` / `pso` / `project` / `health` / `gpu` domains — Plan 3 / Plan 4
- SIGINT graceful cancel for batch
- Shell completion / MCP wrapper / daemon mode
